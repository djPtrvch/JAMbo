# МАСТЕР-ТЗ: Swift-версия JAMbo для Swift Playgrounds

## РОЛЬ И РЕЖИМ РАБОТЫ

Ты работаешь над нативной iOS-версией музыкального приложения JAMbo.
Веб-версия существует и заморожена: она является эталоном поведения.
Новые функции делаются только в Swift-версии.

Работай по принципу:
1. Прочитай нужные файлы и HANDOFF.md.
2. Покажи краткий план изменений.
3. После моего подтверждения реализуй.
4. Проверь результат.
5. Сделай коммит.
6. Обнови HANDOFF.md и файл вехи.

Не начинай писать код, пока план не понятен.
Не расширяй объём задачи.
Не добавляй функции, которых нет в этом ТЗ.
Не рефактори работающий код без явной необходимости.

## 1. ЦЕЛЬ

Создать нативное приложение JAMbo для iPad Pro 11" (M4).
Целевое устройство: iPad Pro 11" M4, альбомная ориентация.
Проект: App Project для Swift Playgrounds, формат .swiftpm.
Публикация: через Swift Playgrounds в App Store.

Веб-версия остаётся эталоном поведения.
Веб-версию не развиваем: допускаются только исправления критических ошибок.

## 2. ОГРАНИЧЕНИЯ SWIFT PLAYGROUNDS

- Только чистый Swift.
- Разрешены системные фреймворки Apple:
  SwiftUI, AVFoundation, Accelerate, Foundation, UniformTypeIdentifiers.
- Запрещены C, C++ и Objective-C цели.
- Запрещены сторонние пакеты.
- Запрещены unsafeFlags.
- Запрещены собственные entitlements и произвольные ключи Info.plist.
- Разрешены только capabilities, доступные в редакторе Swift Playgrounds.
- Фоновое аудио не используем.
- Настройку BACKGROUND AUDIO не добавляем.
- При сворачивании приложения звук может останавливаться: это допустимо.
- Минимальная версия iPadOS: 18.
- Используем Swift 5, а не режим Swift 6.
- Не редактируем вручную swift-tools version и структуру Package.swift,
  созданную Swift Playgrounds.

Если Synchronization недоступен:
- использовать os_unfair_lock с tryLock;
- при занятом замке пропускать кадр, а не блокировать аудиопоток.

## 3. РЕПОЗИТОРИЙ И ВЕТКА

- Работа ведётся в ветке swift.
- Swift-проект находится в ios/JAMbo.swiftpm.
- Одна веха за раз.

- После каждой вехи приложение должно собираться и запускаться на iPad.

## 5. АУДИО-АРХИТЕКТУРА

- Один AVAudioSourceNode.
- Один render-колбэк.
- Стерео.
- Целевая частота: 48 000 Гц.
- AVAudioSession.setPreferredSampleRate(48000).
- Формат узла: 48 000 Гц.
- Системный микшер приводит сигнал к частоте устройства.

Весь звук считается в одном render-колбэке:
дорожки, голоса, эффекты, мастер.

В render-колбэке запрещено:
- выделять память;
- использовать блокировки с ожиданием;
- вызывать ARC-тяжёлые операции;
- вызывать Objective-C;
- использовать print;
- создавать большие Swift-коллекции;
- выполнять файловые операции;
- обращаться к UI.

Разрешено и рекомендуется:
- final-классы;
- UnsafeMutablePointer<Float>;
- @inline(__always) для горячих функций;
- заранее подготовленные буферы;
- атомарные значения;
- SPSC-кольцевая очередь событий;
- кольцевые буферы для измерений.

Денормалы гасить вручную в цепях обратной связи:
- добавка 1e-18;
- или явное обнуление.

Обмен UI и аудио:
- Параметры из UI в аудио: атомарные значения и SPSC-очередь событий.
- Измерения из аудио в UI: кольцевые буферы.
- UI читает измерения по таймеру 60 Гц.
- UI не должен заставлять аудиопоток ждать.

Транспорт:
- Sample-accurate.
- Шаги секвенсора считаются по счётчику сэмплов внутри render-колбэка.
- Без lookahead-планирования.
- Интерфейс TempoSource вводится сразу.
- Первая реализация TempoSource — внутренняя.

Смена звука дорожки:
- Новый экземпляр движка создаётся заранее на фоновом потоке.
- В render-колбэк передаётся в безопасной границе блока.
- Внутри render-колбэка экземпляры не создаются.

## 6. ПЕРЕНОС PLAITS

Цель: перенести все 16 движков Plaits на Swift.

Порядок:
1. Сначала музыкальные движки:
   VA, WAVESHAPE, FM, GRAIN, ADDITIVE, WAVETABLE, CHORDS, SPEECH.
2. Затем шумовые и ударные:
   SWARM, NOISE, PARTICLE, STRING, MODAL, KICK, SNARE, HI-HAT.

Правила порта:
- Переносить по исходникам Plaits (MIT).
- Сохранять алгоритм 1:1.
- Не менять DSP-математику ради «улучшения» звука.
- Не рефакторить перенесённый код, если это может изменить результат.
- Переносить нужные части stmlib:
  random, units, filter, polyblep, delay line, limiter,
  buffer allocator и другие необходимые модули.

Таблицы:
- Таблицы из resources.cc не записывать как большие массивы в Swift.
- Использовать скрипт tools/export_plaits_tables.
- Экспортировать таблицы в двоичные файлы Resources/plaits/*.bin.
- Сохранять типы данных оригинала.
- Swift загружает таблицы при запуске в UnsafeMutablePointer.

Частота:
- Все движки работают на 48 000 Гц.
- Базовая частота:
  a0 = (440 / 8) / 48000.
- Значение 47872.34 не использовать.
- Сдвига ноты нет.

SPEECH:
- Переносим режимы Formant, Phoneme и LPC.
- Привязка harmonics:
  Formant — 0;
  Phoneme — 1/6;
  LPC — 1/3.
- Режим Words не переносим.
- Данные режима Words не переносим.
- Название SAM не использовать.

Эталоны:
- Скрипт tools/golden рендерит текущий plaits.wasm через Node.
- Для каждого движка:
  - 3 набора параметров harmonics, timbre, morph;
  - 2 ноты;
  - длительность 1 секунда;
  - моно;
  - 48 000 Гц;
  - результат Int16.
- Результаты сохранять в Resources/golden/.
- Для SPEECH проверять только Formant, Phoneme и LPC.

SELF-TEST:
- Экран SETTINGS → DIAGNOSTICS → SELF-TEST.
- Swift-движки рендерят те же ноты и параметры.
- Сравнение с эталонами.
- Для детерминированных движков:
  отклонение RMS не больше -60 дБ относительно сигнала.
- Для шумовых движков NOISE, PARTICLE, SWARM, GRAIN:
  использовать тот же генератор случайных чисел,
  сравнивать поотсчётно.
- Показывать таблицу:
  движок / набор параметров / OK или ошибка в дБ.
- Кнопка COPY RESULT.

Лицензия:
- В каждом перенесённом файле комментарий:
  «Ported from Mutable Instruments Plaits and stmlib (MIT),
  Copyright Emilie Gillet».
- Тексты лицензий хранить в Resources/licenses/.
- В приложении экран SETTINGS → LICENSES.

## 7. ОСТАЛЬНОЙ ЗВУК

Сэмплер:
- Чтение через AVAudioFile.
- Приведение к 48 000 Гц и float32.
- Воспроизведение с изменением высоты.
- Кубическая интерполяция.
- Параметры: Start, End, Attack, Decay, Level.
- Поддержка стерео и моно.

Голос дорожки:
- Источник: сэмпл или движок.
- Затем Attack и Decay.
- Затем Level.
- Затем фильтр LP/HP с Resonance.
- Затем Pan.
- Затем дорожка.

Фильтры и EQ:
- Собственные биквады.
- Формулы Web Audio / RBJ.
- У shelf Q не учитывается, как в Web Audio.

FX:
- Посылы: Reverb, Delay, Drive.

Reverb:
- Алгоритмический FDN на 8 линиях.
- Параметры: size, decay, predelay, hpf.
- Не использовать свёртку со сгенерированной импульсной характеристикой.
- Звук сравнивать на слух с веб-версией.
- Запасной вариант, если результат не устраивает:
  свёртка с разделением на блоки через Accelerate.

Delay:
- Стерео.
- Синхронизация с темпом.
- Длительности: от 1/32 до 1 такта, включая триоли и точки.
- Параметры: feedback, hpf, stereo.

Drive:
- Нелинейность.
- Общий полифазный оверсэмплер 4x.

Sidechain:
- Триггер дорожки-источника приглушает остальные дорожки.
- У каждой дорожки свой amount.
- Attack и release берутся из FX.
- Поведение как в веб-версии.

Мастер-цепочка:
EQ → сатуратор → компрессор glue → клиппер → лимитер → громкость выхода.

Мастер:
- EQ до 8 полос.
- Типы фильтров: bell, cut, shelf, notch.
- Без DYN.
- Без Mid/Side.
- Алгоритмы переносить из:
  saturator-worklet.js,
  glue-worklet.js,
  clipper-worklet.js,
  limiter-worklet.js.
- Сохранять константы из начала исходных файлов.
- Сохранять общий оверсэмплер.

Индикация:
- IN, GR, OUT.
- Измеритель с пиками.
- LUFS по BS.1770.
- Скоп: гониометр и осциллоскоп.
- Все измерения считаются в Core и передаются в UI через буферы.

Производительность:
- Целевой ориентир для финальной версии:
  при 8 дорожках, 6 голосах на дорожку и включённых эффектах
  нагрузка не выше 35% одного ядра на iPad Pro M4.
- На промежуточных вехах CPU измерять, но не блокировать разработку.
- Финальная оптимизация — веха S7.
- В интерфейсе должен быть индикатор CPU, как в веб-версии.
