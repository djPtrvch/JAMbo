# SWIFT_MIGRATION.md — перенос JAMbo в Swift Playgrounds

## 1. Цель

Перенести веб-версию JAMbo в нативное iPad-приложение для Swift Playgrounds.

Веб-версия остаётся неизменным эталоном поведения.
Новые функции разрабатываются только в Swift-версии.

## 2. Приоритет решений

При конфликте требований действовать в таком порядке:

1. Не ломать аудио-поток и стабильность приложения.
2. Соблюдать ограничения Swift Playgrounds.
3. Выполнять критерии приёмки текущей вехи.
4. Сохранять поведение веб-версии.
5. Соблюдать правила кода и стиль проекта.

## 3. Целевая платформа

- iPad Pro 11" M4.
- iPadOS 18 или новее.
- Альбомная ориентация.
- App Project для Swift Playgrounds: `ios/JAMbo.swiftpm`.
- Публикация в App Store из Swift Playgrounds.

## 4. Ограничения Playgrounds

- Только Swift и системные фреймворки Apple:
  SwiftUI, AVFoundation, Accelerate, Foundation, UniformTypeIdentifiers.
- Нет сторонних пакетов.
- Нет C, C++ и Objective-C целей.
- Нет `unsafeFlags`.
- Нет ручного редактирования entitlements и произвольных ключей Info.plist.
- Capabilities добавляются только через редактор Playgrounds.
- Swift 5, не режим Swift 6.
- `Package.swift` и swift-tools version не менять вручную.

## 5. Замороженная веб-версия

Веб-версия используется только как эталон:

- для проверки поведения;
- для сравнения звука;
- для аудита функций.

Запрещено менять веб-код для решения задач Swift-версии.

Исключение: критический баг, мешающий аудиту или сравнению.
Такое изменение требует отдельного подтверждения пользователя.

## 6. Рабочий процесс

Для каждой задачи:

1. Прочитай нужные файлы и спецификацию текущей вехи.
2. Покажи план изменений. Код не пиши.
3. После подтверждения пользователя реализуй задачу.
4. Проверь сборку, тесты и критерии приёмки.
5. Сделай коммит.
6. Обнови `docs/handoffs/HANDOFF.md`.
7. Обнови файл текущей вехи.

Никогда не начинай крупное изменение без плана.

## 7. Правила блокеров

Если обнаружен блокер, Claude останавливается и сообщает:

1. Что не работает.
2. Почему.
3. Возможные варианты решения.
4. Рекомендуемый вариант.
5. Влияние на сроки и архитектуру.

Код не пишется до решения пользователя.
