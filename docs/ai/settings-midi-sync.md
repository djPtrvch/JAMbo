# Настройки, MIDI, синхронизация, Ableton Link

Часть спецификации поведения, вынесенная из CLAUDE.md (веб — эталон). Ссылки «см. „Раздел“» ведут в другие файлы docs/ai/ — по таблице в CLAUDE.md.

## Настройки (бутерброд → SETTINGS)
- Хранятся в браузере, отдельно от проектов. Вверху подпись SECTIONS и кнопки разделов (вкладки), ниже — с отступом и чертой — APPEARANCE (тема), под ним открытый раздел (без черты):
- AUDIO ENGINE: SAMPLE RATE (AUTO, 44.1 kHz, 48 kHz; по умолчанию 48 kHz — частота Plaits; у прежних настроек AUTO один раз становится 48 kHz — версия настроек v 2, дальше выбор не трогается) и BUFFER SIZE (AUTO, 128, 256, 512, 1024 — подсказка задержки для Web Audio; Safari может округлить). Смена перезапускает звук (граф строится заново, сэмплы и синты остаются). Ниже — фактические частота, состояние и задержка (строка «Now:»; если браузер дал не ту частоту, что запрошена, — дописано «(48 kHz requested)»). Ниже — MUTE TAILS (рычажок, см. «Дорожки»).
- RECORD (запись с REC; рычажки, хранятся в браузере — settings.record, общие для проектов): QUANTIZE (по умолчанию ON) — нота ставится на ближайший шаг, OFF — на шаг, в котором её нажали (без округления вперёд); OVERDUB (в меню под CHORD, см. sequencer.md; по умолчанию OFF) — OFF: шаги дорожки, по которым проходит запись, очищаются (триг, ноты, p-lock, свой звук), остаются только ноты дубля; очистка начинается с первой записанной ноты дубля и только на его дорожках, в том же пункте UNDO, что и дубль; ON: новые ноты добавляются к нотам шага; STEP SWIPE — палец по шагам секвенсора: LENGTH (по умолчанию) — одна длинная нота от первого шага, PAINT — триг на каждом пройденном шаге (в обе стороны; уже стоящие не снимаются), одна запись UNDO; AUTOMATION RECORDING (по умолчанию ON) — при REC + PLAY поворот ручки дорожки пишет автоматизацию (см. «Автоматизация»), OFF — пишутся только ноты.
- BACKGROUND: BACKGROUND AUDIO (рычажок) — звук продолжает играть, когда Safari свёрнут или экран заблокирован (по умолчанию ON); OFF — при сворачивании звук останавливается.
- SAMPLER: SLICE NOTES — CHROMATIC (по умолчанию) или SCALE: ноты маркеров нарезки в редакторе сэмпла (см. «Редактор сэмпла»); хранится в браузере (sliceMap), общая для проектов. PITCH — SEMITONES (по умолчанию) или SMOOTH: ручка Pitch сэмпла по полутонам или плавно; общая для проектов.
- APPEARANCE (под вкладками): тема SYSTEM (как на iPad), LIGHT или DARK; FX ANIMATION (Swift; по умолчанию ON) — картинки FX в окне сэмпла, пока регулируют ручки FX (см. «Анимация FX» в fx-eq.md).
- DUCK (прежде SIDECHAIN; на пробу; если не понравится — уберём): DUCK SENDS — три рычажка: REVERB (по умолчанию OFF), DELAY (OFF), DRIVE (ON); ON — вход посыла этого эффекта приглушается тем же sidechain, что и выход дорожки (хвосты эффекта звучат), OFF — нет. Хранятся в браузере вместе с настройками (scSends: rev, dly, drv), общие для проектов; не в проекте, не в .jambo, не в MIDI и автоматизации; применяются сразу и при запуске.
- DEFAULTS (Swift): как запомнить и сбросить свои значения ручек по умолчанию (SHIFT + удержание ручки, двойной тап — см. sequencer.md), число запомненных, FORGET ALL (красная) — забыть все.
- MORPH (Swift): ALL TRACKS по умолчанию ON.
- SCALE: MASTER WINDOWS SCALE — 48 dB (по умолчанию), 32 dB или 16 dB: низ шкалы дисплеев уровня и стержней IN/OUT в окнах компрессора, клиппера и лимитера (верх — 0 dBFS), WAVE сатуратора (−SCALE в середине) и его SPECTRUM (до −2·SCALE). Хранится в браузере (limScale), общая для проектов; в окнах модулей кнопки SCALE нет.
- OUTPUT: выбор выхода (где браузер это умеет — setSinkId; в Safari на iPad выход выбирается в Пункте управления, об этом подсказка) и входа аудиоинтерфейса (запоминается; вход приложение пока не использует). ALLOW ACCESS — разрешение, чтобы видеть имена устройств.

## MIDI (бутерброд → MIDI)
- Вкладки DEVICES, MAPPING, NOTES. Настройки MIDI и маппинги хранятся в настройках приложения (UserDefaults), общие для всех проектов. MIDI (CoreMIDI) подключается при запуске: слушаются все входы, которые видит iPadOS (USB, сеть, Bluetooth); список устройств обновляется при подключении и отключении.
- DEVICES: вход (ALL INPUTS или один), выход обратной связи по умолчанию (NONE или устройство: значения ручек уходят туда, кольца энкодеров Midi Fighter Twister повторяют экран; выбранное, но отключённое устройство — серый пункт NOT CONNECTED (выбор сохраняется)) и раздел BLUETOOTH MIDI: CONNECT (поиск и подключение BLE MIDI; тап по подключённому — отключить) и ADVERTISE (iPad сам виден другим как Bluetooth MIDI-устройство) — системные окна iPadOS; без capability Bluetooth кнопки неактивны.
- MAPPING: MIDI LEARN — меню закрывается, внизу экрана (поверх пианоролла) полоса LEARN; тап по ручке или кнопке выбирает цель (её действие не выполняется; цель — жёлтая рамка, назначенные — полупрозрачная жёлтая заливка и в правом верхнем углу, с отступом от рамки, тип и номер маппинга обычным шрифтом: «CC 20», «N 36»; у маленьких кнопок M, S, ● в MIX — рядом, справа от кнопки), движение контроллера (CC или нота) назначает его; один источник — одна цель, у цели один источник (новый заменяет старый). Двойной тап по цели — окно MIDI MAP. UNMAP снимает маппинг цели, DONE — выход (закрывает и окно MIDI MAP). На полосе LEARN — TURN / PRESS: тап по ручке выбирает её поворот (KNOB 2.1) или нажатие (KNOB 2.1 PRESS); у назначенной ручки — метки поворота («CC 20») и нажатия («P 36»). В режиме TURN на ручках видны метки поворота, в PRESS — метки нажатия; оба назначения действуют одновременно. Список маппингов: источник и устройство («CC 5 · CH 1 · Xjam», ANY INPUT — любой вход), цель (у глобальной ручки — параметр и место: «KNOB 1.3 (Level · MIX)»), тип управления и условие — GLOBAL, PAGE или CLIPS; ✕ — удалить; тап по строке — окно MIDI MAP, после закрытия — снова меню; ниже — CLEAR ALL. Над списком закреплена строка CROSSFADER (кроссфейдер перехода MIX): его маппинг или «Not mapped», тап — окно MIDI MAP. Переключатель KNOB PRESS = TOUCH (по умолчанию ON): нажатие ручки — как палец на ручке; OFF — действие Action из окна MIDI MAP. MIDI подключается при запуске, если маппинги уже есть.
- Окно MIDI MAP (как в Drambo): плавающее, не закрывает экран, перетаскивается за заголовок (положение запоминается до перезагрузки); в заголовке слева Unmap (снять маппинг; всегда видна, без маппинга серая), по центру цель (KNOB 2.1, PLAY…), справа ✕. Пока окно открыто, тап по другой цели в режиме LEARN переключает окно на неё, а движение контроллера задаёт Number, Channel, Event type и Input port. Строки (значение справа, «›» — выбор на месте списка, стрелка назад — обратно). В самом верху отдельно Preset — пресет маппингов (набор под контроллер; хранится в браузере, общий для проектов): имя последнего загруженного или сохранённого («*» — маппинги с тех пор изменены, None — нет); в списке сохранённые (с числом маппингов), тап загружает — его маппинги заменяют все нынешние; ниже Save current as new… (имя — до 40 знаков), Save to «…» (перезаписать текущий), Rename…, Delete. Дальше по порядку: Number — ввод числом 0–127 (× очищает; если номер занят другой целью — жёлтое «used by …», при записи маппинг переходит сюда); Channel — сетка 1–16; Event type — CC или Note; Control type — Button momentary (пока нажата), Button toggle (нажатие включает, следующее выключает), Button latch (переключатель на контроллере: 127 — включено, 0 — выключено; кнопки удержания — LFO1–3, ENV, FX, MOD, шаги, клавиши, аккорды — держатся, пока включено; кнопки с состоянием нажимаются, только если горят не так, как переключатель; UNDO, REDO, OCTAVE, стрелки сетки — нажатие при включении; LEARN ставит momentary, latch выбирают в окне), у ручек ещё Continuous absolute (0–127) и Continuous relative (энкодер шлёт шаги); Encoder (у relative, сразу под Control type) — Offset 64 (65 вверх, 63 вниз, как ENC 3FH/41H у Twister), 2’s complement (1 вверх, 127 вниз), Signed bit (1 вверх, 65 вниз); Range (только ручки) — график от входа 0 до 127: левый конец (Min) и правый (Max) тянут вверх-вниз, Invert меняет их местами (энкодер крутит в обратную сторону), Reset — 0–100%; Condition — когда маппинг работает: Global (на всех страницах и вкладках), Current page (только пока сетка ручек показывает эту страницу; пункт называется просто Current page), Clip launcher (только пока открыта сетка паттернов). У назначенной ручки (KNOB, не PRESS и не кнопки) в условии Current page внизу окна — Apply to all pages (решение пользователя, Swift): маппинги всех 16 ручек этой страницы копируются на все страницы сетки ручек (TRACK, FX, MOD, MIX, MST) с тем же источником, типом, диапазоном и портами; на каждой странице ручка управляет параметром своей позиции на этой странице. Копия заменяет маппинг той же ручки на странице и забирает источник у другой цели в её условии; дальше маппинги страниц правятся отдельно. Ручка в условии Global запоминает место назначения — страницу и дорожку — и всегда управляет этим параметром, что бы ни было на экране (громкость T3 в MIX — только она); если параметр сейчас не на экране — его основное значение, без p-lock. Метка в LEARN видна только там, где параметр на экране. Один источник может быть назначен в разных условиях: действует самое точное из действующих — Clip launcher, затем Current page, затем Global; у цели в каждом условии свой маппинг. Новый маппинг в сетке паттернов (и любой маппинг ячейки или строки сетки) — Clip launcher, иначе Global. Окно правит маппинг своего условия, даже если оно сейчас не действует. Отдельным блоком ниже, рядом: Input port — вход, с которого слушать (Any или устройство; при LEARN — тот, откуда пришло сообщение); Feedback port — Default (выход из DEVICES), None или выход. Кнопочные типы на ручке: нажатие — верх диапазона, отпускание (или второе нажатие toggle) — низ. Обратная связь (по таймеру интерфейса, каждый кадр (60 Гц), только изменения; фейдеру (Continuous absolute), который двигают на контроллере, — без эха, пока идут сообщения и 0,3 с после; у источника — самое точное действующее условие, как при управлении, с любого входа: Global ручки с другим Input port не перебивает Current page): ручка шлёт значение, которое показывает экран (p-lock зажатого или играющего шага), в своём диапазоне Range; ручка GLOBAL не на своём месте — основное значение параметра места; BPM, LEVEL, XFADER (только во время перехода) — так же; кнопка — 127, когда горит (PLAY играет, REC, PATTERNS, EQ, ROLL, METRONOME, CHORD, зажатые LFO/ENV/FX/MOD, MORPH включён, выбранные T n / MIX / MST, MUTE, SOLO, ARM, ARM MST, триг на STEP, зажатые KEY и PROG CHORD, играющие ячейки и строки сетки), иначе 0; UNDO, REDO, OCTAVE, стрелки сетки — всегда 0. Нажатие ручки (PRESS) ничего не шлёт: у энкодеров с кнопкой (Twister) этот источник задаёт цвет подсветки. После переподключения устройств значения шлются заново.
- Ручки назначаются по позиции в сетке 4×4 (KNOB столбец.ряд) и управляют тем, что ручка показывает в текущем режиме (дорожка, FX, MOD, MIX, MST); как палец: с зажатым шагом — p-lock, с зажатыми LFO/ENV — степень назначения. Вращение энкодера — одна запись в UNDO (пауза 0,3 с завершает её).
- Кнопки: PLAY, REC, PATTERNS, EQ, ROLL (пианоролл, на месте AUTO), UNDO, REDO, METRONOME, CHORD, OCTAVE ▲ / ▼ (тап); LFO1–3, ENV, FX, MOD, MORPH (удержание: нажатие — зажать, отпускание — отпустить; MORPH без UNDO переключает режим); T1–T16, MIX, MST (выбор); MUTE n, SOLO n, ARM n (кнопки M, S, ● у ручек громкости в MIX; работают и вне MIX), ARM MST (● MASTER — запись мастера); ячейки сетки паттернов (CLIP Tn · строка — как тап: запуск, остановка, новый паттерн; строка — место в окне строк 1–8, окно сдвигается стрелками), строки (ROW n — запуск строки на месте n окна) и стрелки окна строк (GRID ▲, GRID ▼) — их маппинги в условии Clip launcher (по умолчанию) или Global — запуск паттернов и при закрытой сетке; Current page у них нет ( в режиме LEARN тап по PATTERNS и выбирает её целью, и открывает сетку — так можно выбрать ячейку или строку); клавиши пианоролла по позиции (KEY 1…25, слева направо; за числом клавиш на экране — ничего) и аккорды строки прогрессии (PROG CHORD 1…8; только с CHORD) — как палец: нажатие — нота звучит, становится выбранной и держится, пока держат (с REC пишется, длина — по удержанию), сила — 1; шаги секвенсора открытой страницы (STEP 1…16) — как палец: нажатие держит шаг (с энкодерами — p-lock), быстрое отпускание ставит или снимает триг (обратная связь — горит, если на шаге триг). Регулятор темпа BPM маппится как ручка (Continuous absolute — диапазон 40–240 BPM по Range, relative — шагами; кнопочные типы — края диапазона; обратная связь — значение). Регулятор громкости на измерителе справа (LEVEL) маппится так же, как ручка: весь ход шкалы −60…0 dB по Range; у дорожки — громкость выбранной дорожки (по SETTINGS → LEVEL), при MIX и MST — громкость выхода. Темп с MIDI — целыми BPM. Кроссфейдер перехода MIX (XFADER) маппится как ручка, по умолчанию Global; действует только во время перехода. CC ≥ 64 — нажатие, < 64 — отпускание; нота — Note On и Note Off. Цели RATIO нет (RATIO компрессора — только в его окне); прежние маппинги на неё при загрузке настроек удаляются. Нажатие ручки (KNOB c.r PRESS) — своя цель. При KNOB PRESS = TOUCH — как палец: нажатие — касание ручки (тап по LFO/ENV переносит назначение), двойное нажатие за 0,35 с — двойной тап. При OFF — строка Action окна MIDI MAP: Reset (с зажатым LFO/ENV — снять назначение, с зажатым шагом или SHIFT — снять p-lock, иначе — значение по умолчанию), Param (параметр этой позиции: нажатие — Max, отпускание — Min) или любая кнопка.
- MIDI дорожки (меню звука → MIDI; вкладки NOTES в меню MIDI нет): у каждой дорожки, в проекте, с UNDO. MIDI IN — устройство (ALL INPUTS, одно или NONE) и канал: ALL — дорожка играет ноты, только пока выбрана; 1–16 — всегда (одна нота может играть на нескольких дорожках). Ноты с MIDI-входов играют как пианоролл (с REC — записываются); ноты и CC, назначенные на кнопки и ручки, не играют; нота держится до Note Off. MIDI OUT — устройство (NONE — дорожка звучит сама) и канал 1–16: с выходом свой звук дорожки молчит, её ноты (шаги, пианоролл, клавиатура, MIDI IN) уходят на устройство с velocity = Level ноты, в момент, когда звучал бы звук, + MIDI OFFSET; mute/solo глушат и MIDI, стоп отпускает ноты.

## Синхронизация (бутерброд → SYNC)
- Меню SYNC (как MIDI: стрелка назад, прокрутка; настройки — в браузере, settings.sync, общие для проектов, не в проекте). Разделы с заголовками и чертой между ними:
  - GENERAL: SYNC QUANTUM — 1, 2, 4 или 8 BARS (по умолчанию 1) — длина фразы для выравнивания старта с другими устройствами (Ableton Link).
  - MIDI CLOCK: MIDI CLOCK SYNC ON/OFF (по умолчанию OFF; включение подключает Web MIDI); CLOCK SOURCE — SEND (JAMbo ведущий, отдаёт клок) или RECEIVE (ведомый, принимает); у SEND — CLOCK OUTPUT (ALL OUTPUTS или один выход), у RECEIVE — CLOCK INPUT (ALL INPUTS или один вход; по умолчанию ALL INPUTS): клок, Start, Continue и Stop — только с этого входа, вход нот и маппингов (MIDI → DEVICES) на него не влияет; смена входа — темп и привязка шагов заново (S14d); SYNC START/STOP ON/OFF (по умолчанию ON); MIDI OFFSET — сдвиг в ms (−200…+200, по умолчанию 0; стрелки ◀ ▶ по 1 ms, удержание — повтор; палец по значению вправо-влево — быстро, 1 ms на 3 px): плюс — отдаваемый клок, Start и Stop позже, при приёме — свои шаги позже тиков клока; минус — раньше.
  - ABLETON LINK: ABLETON LINK — в веб-сборке неактивен (серый рычажок, подпись «unavailable in this build»; Link — только в нативном приложении, см. «Ableton Link»), IN-APP NOTIFICATIONS ON/OFF (по умолчанию ON — строка вверху экрана на 2,5 с, когда кто-то подключается к сессии или уходит, как в других приложениях), SYNC START/STOP ON/OFF (по умолчанию OFF). Сам Link — в нативном приложении (этап 9); в браузере остальные настройки Link только сохраняются (подсказка в меню). LINK OFFSET — сдвиг в ms для Link (−200…+200, стрелки ◀ ▶, как MIDI OFFSET; пока только хранится). В Swift-версии (S14, перед App Store) раздел ABLETON LINK скрыт до этапа 9: неработающей функции на виду быть не должно; настройки Link хранятся. В подсказке SYNC QUANTUM нет упоминания Link.
- Полоса фазы под темпом: тонкая (1 px) жёлтая полоса внизу поля BPM (отступ 7 px от нижнего края кнопки, 12 px от боковых); надпись выровнена по полосе — «BPM» от её левого края, число темпа — до правого, разделена на 4 отрезка на такт × SYNC QUANTUM (1 BAR — 4, 2 — 8, 4 — 16, 8 — 32); при игре загораются отрезки до текущей доли (по часам секвенсора), в начале фразы — снова один; стоп — все серые. Показывает синхронизацию тактов.
- MIDI-клок (src/sync.ts), 24 тика на четверть: SEND — тики 0xF8 на выбранный выход с метками времени Web MIDI заранее на ~100 ms, темп — темп проекта; при PLAY (если SYNC START/STOP) — 0xFA в момент первого шага, первый тик — в тот же момент (сетка тиков встаёт на старт), при стопе — 0xFC; между запусками клок идёт дальше. RECEIVE — темп по наклону времени последних 48 тиков (наименьшие квадраты), транспорт идёт по этому темпу (точнее целого BPM), BPM проекта показывает его округлённым (без UNDO); шаги транспорта подтягиваются к времени своих тиков (шаг 1/16 = 6 тиков; ошибка фазы убирается на 25 % за шаг) — фаза не уплывает; с SYNC START/STOP: Start — игра с первого тика после Start, Continue — продолжить, Stop — стоп; PLAY своей кнопкой при входящем клоке — от ближайшего тика; клока нет дольше 0,5 с или RECEIVE выключили (MIDI CLOCK SYNC — OFF или SEND) — свой темп (темп проекта). Сообщения реального времени (0xF8–0xFF) идут мимо маппингов. В Safari на iPad Web MIDI нет — клок заработает в нативном приложении.
- Проверка (Chromium с подменённым Web MIDI — фальшивые вход и выход): SEND при 120 BPM — Start через 0,6 ms после PLAY, первый тик в момент Start (0,00 ms), интервал тиков 20,833 ms (120,00 BPM), разброс 0; Stop при стопе; RECEIVE — внешний клок 123,4 BPM: после Start игра идёт с первого тика, темп 123,40 BPM (шаг 121,556 ms — как у клока), BPM проекта 123, Stop останавливает.
- MIDI-клок в Swift-версии (S13e; Core/Sequencer/ClockPlan.swift, ClockFollower.swift, UI/AppModelSync.swift, Audio/MidiHost.swift). Поведение — как в вебе (выше); отличия и устройство:
  - Время: все моменты — секунды часов хоста (mach_absolute_time); момент шага — когда шаг слышен: время блока колбэка + задержка выхода (AVAudioSession.outputLatency, запоминается при запуске звука и смене маршрута — с USB-аудио система отдаёт то 1, то 11 мс). Настройки SYNC — в UserDefaults (settings.sync), общие для проектов.
  - SEND: планировщик ClockPlan — в Core (без CoreMIDI), зовётся по таймеру интерфейса (drain, 60 раз в секунду) и ставит тики, Start и Stop на 100 мс вперёд (при отрицательном MIDI OFFSET — дальше на величину сдвига); MidiHost отправляет их с метками времени CoreMIDI — точность не зависит от главного потока. При игре тики идут по сетке шагов из колбэка (PlayClock), 6 тиков на шаг; Start и первый тик — в момент шага 0. На старте отправленные, но не прозвучавшие тики сбрасываются (MIDIFlushOutput), тики свободного хода до старта отправляются заново. Приложение стояло — пропущенные тики не догоняются пачкой.
  - RECEIVE: время тика — метка времени пакета CoreMIDI (метка 0 — «сейчас»); разбор — в потоке CoreMIDI, ClockFollower — на главном потоке. Темп — наклон по 48 тикам, не раньше 4 тиков окна (по одному-двум тикам USB дрожит); точный темп — в звук, округлённый — в BPM проекта (без UNDO). Start — игра с первого тика после Start: шаг 0 — в кадре, который слышен в момент тика + MIDI OFFSET; если этот кадр уже прошёл — не дальше 0,9 шага в прошлое (опаздывает только шаг 0, дальше шаги по клоку). Поправка фазы — в колбэке: раз на шаг интерфейс шлёт CoreEvent.clockPhase (номер следующего шага и кадр, в котором он должен звучать по клоку), секвенсор сдвигает фазу источника такта на 25 % ошибки; ошибка не меньше шага — без поправки (как в вебе).
  - Шаг 0 заново привязывается к ближайшему тику: после PLAY своей кнопкой, после пропажи клока дольше 0,5 с (отключили устройство) и после перезапуска звука. Пропуск тиков короче 0,5 с (интервал больше 2,5 обычных и не меньше 60 мс — дрожание Bluetooth MIDI не пропуск) — окно темпа заново, пропущенные тики досчитываются, привязка прежняя. Клок пропал или RECEIVE выключили — в звук возвращается темп проекта.
  - Смена настройки MIDI подключает только новые источники и отключает пропавшие; подключённые не трогаются (иначе терялись тики и проседал темп).
  - Проверено на iPad с Digitakt по USB в режиме USB MIDI: RECEIVE, SYNC START/STOP (выкл. — свои PLAY и STOP независимы), SEND. В режиме USB AUDIO/MIDI iPad уводит выход на Digitakt, звука нет и секвенция тормозит — из приложения не исправить. Тесты Core — ClockPlanTests, ClockFollowerTests.
- Источник такта (TempoSource; src/tempoSource.ts — интерфейс и свой источник без зависимостей, src/tempo.ts — текущий источник приложения): kind ('internal' | 'link'), tempo() (BPM), setTempo(bpm), beatAt(time) и timeAt(beat) (доля такта ↔ момент, секунды часов планировщика: в браузере performance.now() / 1000, в нативном — время хоста), isPlaying(), requestStart() / requestStop(), onChange(cb) → отписка. QUANTUM_BEATS = 4 (квант — 1 такт), шаг — 1/4 доли (STEPS_PER_BEAT). В веб-версии один источник — InternalTempoSource: темп проекта (или внешнего MIDI-клока), точка отсчёта — доля 0 в момент старта; смена темпа переносит точку на долю только что сыгранного шага (доля не прыгает, как прежде: новый темп — со следующего шага); подстройка к MIDI-клоку и пропуск шагов после фона — сдвигом фазы источника; PLAY стартует сразу. Планировщик (transport.ts) ставит шаг n в момент timeAt(n/4); граница такта для запуска паттернов, строк и акцента метронома — доля, кратная QUANTUM_BEATS (isBarStart); Delay по темпу и длина огибающей живой ноты — темп источника (tempo()). Поведение прежнее. Проверка: node --experimental-strip-types scripts/tempo-check.mjs — beatAt и timeAt взаимно обратны (ошибка 1e-13), шаг n на 120 BPM — n·0,125 с (0,0000 мкс на 100 000 шагах), смена темпа 120 → 97,3 без скачка доли, шаги совпадают с прежним планировщиком (nextTime += длина шага) при сменах темпа на ходу (0,0000 мкс); в Chromium — полоса фазы, запись с REC, MIDI-клок SEND/RECEIVE и scripts/click-check.cjs delay (0 щелчков) — как раньше.

## Ableton Link (нативное приложение, этап 9)
- Только в нативном приложении iOS: в веб-прототип и gh-pages Link и LinkKit не попадают (в веб-версии — только интерфейс TempoSource, см. «Синхронизация»). Решения: quantum — 1 такт (4 доли = 16 шагов); темп сессии главнее темпа проекта; кроссфейдер переходов темп не меняет; диапазон 40–240 BPM не меняется (темп сессии вне диапазона отыгрывается кратно 2); пункт LINK — уже в меню (SYNC → ABLETON LINK), нового не добавлять.
- B0. Спайк в Swift Playgrounds — первый шаг этапа 9, до остального кода Link: минимальное приложение (один экран: кнопка включения Link — ABLLinkSettingsViewController, строка состояния — ABLLinkIsConnected и темп). Шаги (на первом провале — остановиться и записать, где): 1) LinkKit.xcframework как бинарная зависимость (Swift-пакет с binaryTarget из приватного места, SDK публично не раздавать) — проект собирается с импортом LinkKit; 2) флаг -lc++ — без ошибок линковки; 3) Local Network через редактор capabilities (если пункта нет — записать) — при первом запуске iPad спрашивает доступ к локальной сети с нашим текстом; 4) entitlement com.apple.developer.networking.multicast — запросить у Apple для App ID, подключить к подписи — сборка на устройство подписывается с ним; 5) iPad рядом с компьютером с Ableton Live (одна Wi-Fi-сеть), в Live включён Link — ABLLinkIsConnected = true, темп меняется в обе стороны, старт на границе такта; 6) если шаг 4 не проходит — записать причину, план Б: те же исходники на облачном Mac (Xcode), в Playgrounds — внутренний источник такта. Результат — таблица «шаг / проходит / что записать». Ключ ABLLinkStartStopSyncSupported необязателен (без него нет общего старта и остановки).
- Лицензия и SDK: LinkKit.xcframework из официального релиза, Ableton Link SDK License v2.0; SDK, документацию и тест-план не коммитить (.gitignore), на сборке — из приватного хранилища; тексты из материалов SDK в публичные файлы не копировать. Link не продаётся покупкой внутри приложения; значки и логотипы Link — только из SDK, интерфейс — по руководству SDK (оно главнее стиля Ink).
- Код: в Swift тот же протокол TempoSource и InternalTempoSource; LinkTempoSource — в отдельном модуле, только в сборке с LinkKit (#if canImport(LinkKit)); без Link приложение собирается и работает на внутреннем источнике; пока Link не подтверждён в сборке, раздел ABLETON LINK скрыт.
- Подключение: LinkKit.xcframework, -lc++; Info.plist — NSLocalNetworkUsageDescription (на английском), ABLLinkStartStopSyncSupported = YES (если доступно); entitlement com.apple.developer.networking.multicast. ABLLinkNew на главном потоке при запуске (начальный темп — темп открытого проекта), живёт всё время работы, ABLLinkDelete при завершении.
- Источник такта: Link включён и подключён — темп и фаза из Link, иначе — внутренний. Включает и выключает Link только пользователь (настройки Link); состояние видно в интерфейсе. Один источник за раз: пока Link включён, другая синхронизация (MIDI-клок) отключена.
- Фаза: quantum — 1 такт, шаг — 1/4 доли; шаги в аудиоколбэке — по доле Link с учётом задержки выхода (AVAudioSession.outputLatency, пересчёт при смене маршрута) и длины буфера; расхождение с другими участниками не больше 3 мс. Паттерны другой длины крутятся относительно общей сетки тактов; запуск паттерна и строки — по границе такта сессии.
- PLAY и остановка: с другими участниками PLAY стартует на ближайшей границе такта сессии (кнопка мигает жёлтым, пока ждёт), без участников — сразу. Start/Stop Sync включён — старт и остановка общие для сессии (чужие двигают наш транспорт, наши расходятся по сессии), выключен — только локально.
- Темп: жест по BPM предлагает темп сессии; при входе в сессию берётся темп сессии, включение Link без участников темп не меняет; темп сессии вне 40–240 BPM — игра вдвое быстрее или медленнее (кратно 2), показан темп сессии; пока Link включён, темп проекта при открытии не применяется, кроссфейдер переходов темп не меняет; Delay и метроном — по темпу сессии.
- Интерфейс: пункт LINK (SYNC → ABLETON LINK) открывает ABLLinkSettingsViewController (вид не настраивается, отличается от Ink — допустимо); у поля BPM значок состояния из SDK (по руководству): выключен — приглушён, включён без участников — контур, подключён — заполнен; надписи на английском.
- Фон и маршрут: при уходе в фон ABLLinkSetActive(false), если не играет (играет с BACKGROUND AUDIO = ON — остаётся активным); при возврате ABLLinkSetActive(true). Смена маршрута (наушники, AirPlay, USB) — задержка выхода пересчитывается.
- Не делаем: Link в веб-версии, на Android, Mac и Windows; Link Audio; программное включение Link; продажу Link покупкой.
- Проверка: все пункты тест-плана Ableton из SDK (темп, фаза, старт и стоп, задержка, фон); с Ableton Live и вторым iOS-приложением — темп, старт и стоп, фаза совпадают на слух, расхождение не больше 3 мс; вход и выход участников, смена маршрута, фон и возврат; сборка без Link проходит и работает на внутреннем источнике.
