# Мастер: клиппер и лимитер

Часть спецификации поведения, вынесенная из CLAUDE.md (веб — эталон). Ссылки «см. „Раздел“» ведут в другие файлы docs/ai/ — по таблице в CLAUDE.md.

## Клиппер мастера
Стоит на мастере между компрессором и лимитером.
- Ручки (колонка 3 в режиме MST, все плавные; вертикальный drag, мультитач; двойной тап без удержания ничего не делает; LFO и p-lock на них не назначаются):
  - 3.1 INPUT (на ручке подпись Input; ниже в тексте — DRIVE): 0…+12 dB, шаг 0.1, по умолчанию 0 — усиление перед клиппером (чем больше, тем сильнее срезаются пики), без автокомпенсации громкости.
  - 3.2 CEILING: −12…0 dB, шаг 0.1, по умолчанию −1.0 dB — уровень, выше которого сигнал срезается.
  - 3.3 SOFTNESS: 0…100%, по умолчанию 30% — 0% жёсткий клип, 100% мягкий (плавный вход в клип).
  - 3.4 BASS (защита басов): 20…300 Hz, логарифмическая шкала, по умолчанию OFF — при включённой защите всё ниже этой частоты проходит мимо клиппера без искажений, клипуется только верх; первые 5% хода ручки — OFF (клип по всему диапазону, на дисплее «OFF»).
  - Значения: «+3.0 dB», «-1.0 dB», «30%», «100 Hz» или «OFF» — в центре ручки, как у всех ручек (подпись под ручкой).
- Звук (AudioWorklet, стерео):
  - Вход · DRIVE; каналы независимо (без stereo link).
  - Кроссовер Linkwitz-Riley 4-го порядка на частоте BASS (по два каскада Butterworth 2-го порядка на полосу); сумма НЧ + ВЧ без обработки равна входу по амплитуде (±0.1 dB) на любой частоте. BASS = OFF — кроссовер обходится (полосы не делятся).
  - Клипуется только ВЧ-полоса; НЧ идёт без обработки, с задержкой, равной задержке оверсэмплера ВЧ-полосы (фазы совпадают при сложении).
  - Оверсэмплинг 4× (полифазный FIR) вокруг нелинейности, фиксированный.
  - Передаточная функция ВЧ-полосы: u = x / Ceiling, колено k = 1 − 0.6·Softness; |u| ≤ k: y = u; |u| > k: y = sign(u)·(k + (1 − k)·tanh((|u| − k)/(1 − k))); выход = y·Ceiling. При Softness 0 — жёсткий клип (y = clamp(u, −1, 1)).
  - Выход = НЧ (без обработки) + клипованная ВЧ. Пики на низах не срезаются — их ловит лимитер; чем выше BASS, тем меньше срезаются пики бочки и баса.
  - Float, без денормалов, без щелчков при смене параметров (значения сглаживаются за 20 ms, коэффициенты кроссовера при смене частоты интерполируются).
  - MIX (clip.mix, 0…100 %, по умолчанию 100 %; в проекте, в старых — 100 %; ручки нет — поле в окне; p-lock и LFO/ENV не принимает): выход = сухой·(1 − MIX) + клипованный·MIX, сухой — исходный вход (до DRIVE) с задержкой клиппера (32 отсчёта, фазы совпадают); MIX 100 % — прежний звук.
  - UNITY и AUDIT (только пока открыто окно; при закрытии окна и загрузке проекта выключаются, не в проекте): UNITY — после MIX усиление −DRIVE dB (IN, GR, OUT — реальные); AUDIT — на выходе срезанное: вход после DRIVE (задержан) минус выход клиппера (до MIX), кроссфейд 10 ms.
  - Телеметрия: раз в 256 отсчётов кадр [пик после DRIVE, срез в dB (наибольшее из окон 10 ms, закончившихся в кадре, иначе последнее окно), пик выхода] — только пока виден блок CLIP (MST) или окно; кольцевой буфер clipTele (2048 кадров) на главной стороне. Вид WAVE окна: воклет держит кольцо 4096 отсчётов по каналам (вход после DRIVE, задержанный на 32 отсчёта, и выход после MIX) и раз в ~33 ms шлёт снимок — 1024 отсчёта входа и выхода вокруг наибольшего пика последних 2048 отсчётов (канал с большим пиком; окно сдвигается, чтобы лежать в кольце), только пока окно открыто и вид WAVE.
  - Mix есть (0…100 %), выбора кривой, переключателя оверсэмплинга и внешнего sidechain нет.
- Индикация — блок CLIP боковой панели мастера (общий компонент LevelBars, см. «Индикация мастера»): IN — уровень после DRIVE, до клиппера (весь диапазон), риска CEILING; GR — насколько срезан пик, шкала 0…−12 dB: 20·log10(|y|/|x|) для самого большого пика в окне 10 ms по всему сигналу (НЧ учитывается как есть: если клипуется только верх, GR меньше), без клипа — 0; OUT — уровень на выходе клиппера.
  - BYPASS CLIP — SHIFT + тап по кнопке CLIP (на месте LFO1 при MST, см. «Кнопки мастера»): включает и выключает, с SHIFT оранжевая, пока bypass включён; в bypass клиппер полностью отключён (кроссфейд 10 ms, задержка не меняется), столбцы серые, GR на нуле.
- Окно клиппера (src/ui/clipper.ts, на общей основе src/ui/masterwin.ts): тап по блоку CLIP при MST (или по кнопке CLIP). На месте EQ (справа общий измеритель; закрывает окно сэмпла, индикацию слева и сетку ручек; PATTERNS, EQ, редактор сэмпла, браузер, AUTO и окна модулей не открыты одновременно). Закрывается крестиком ✕ и выходом из MST; открытость, UNITY, AUDIT и FREEZE не в проекте. Параметры общие с ручками 3.1–3.4 (Twister по позиции двигает элементы окна). Нижней панели нет.
  - Строка вверху (как ряд EQ, 48 px; Swift: INPUT и CEILING — поровну до правого края TRANSFER, SOFTNESS и BASS — поровну до PRESETS): MASTER CLIP, поля INPUT, CEILING, SOFTNESS, BASS (формат — как на ручках, BASS — OFF в первых 5 % хода), за тонкой чертой MIX; палец вверх-вниз (240 px на весь диапазон), двойной тап — ввод числом (окно вверху окна; BASS — «off»); кнопки VIEW (WAVE / LEVEL, тап переключает; в настройках браузера — clipDisplay, не в проекте), UNITY, AUDIT (жёлтые, пока включены), BYPASS (тот же BYPASS CLIP, рядом с крестиком) и крестик; SCALE — в SETTINGS. Поле, которое меняют (палец, ручка, Twister, UNDO), — в жёлтой рамке и ещё 400 ms; при BYPASS поля серые.
  - TRANSFER (не шире 35 %): обе оси −30…0 dB (не от SCALE) — по горизонтали источник до INPUT, по вертикали выход клиппера до MIX; сетка через 6 dB, диагональ 1:1, серая полоса колена от x_k = x_c + 20·log10(k) до угла x_c = CEILING − INPUT, кривая (белая, 1.5 px) по формуле клиппера, белый пунктир CEILING, живая точка — пик последнего кадра после INPUT минус INPUT, на кривой; пока идёт срез, участок кривой от начала колена до точки — оранжевый. Ручка-угол (кружок 28 px) в (x_c, CEILING): палец — CEILING = y, INPUT = CEILING − x (с округлением до 0.1, в пределах диапазонов); SOFTNESS пальцем на кривой не меняется — только полем и ручкой 3.3.
  - DISPLAY, вид WAVE (по умолчанию): снимок ~20 ms (1024 отсчёта) вокруг пика, 30 раз в секунду; ось — амплитуда −1…+1, сетка 0, ±0.5, ±1; вход после INPUT — серая заливка от нуля с тонким контуром (выше ±1 — светлая метка у края), срезанное (где выход по модулю меньше входа) — оранжевая заливка ~25 %, выход после MIX — оранжевый контур 1.5 px, белые линии потолка ±10^(CEILING/20) (2 px) с числом справа, в углу L или R. Вид LEVEL: пик в dB за 4 с (как у лимитера и компрессора), низ — по SCALE; вход — серая заливка с контуром, выход — оранжевый контур и заливка ~15 %, GR — оранжевая заливка ~25 % от верхней кромки (без линии), подписи пиков GR (≥ 1 dB, не чаще 100 ms, до 6), белая линия CEILING с числом.
  - Линии потолка в обоих видах тянутся вверх-вниз (±22 px, приоритет выше FREEZE; в WAVE значение — 20·log10 амплитуды по положению пальца, в LEVEL — по шкале); тап по дисплею — FREEZE (WAVE держит последний снимок, LEVEL — историю), надпись FREEZE слева вверху; повторный тап снимает. Мультитач (угол, линии, поля); двойной тап ничего не делает; отмена — UNDO.
  - Блок CLIP справа — тот же LevelBars и данные, что слева; IN и OUT — по SCALE.
- Проверка окна: node scripts/clipper-check.mjs [прежний clipper-worklet.js] — MIX 100 % против прежнего: −240 dB (совпадает) на шуме при INPUT +6, +12 с BASS 120 Hz, +3 с CEILING −6 и SOFTNESS 100; статическая характеристика (синус 200 Hz) против формулы TRANSFER в пяти точках (INPUT 0/6/12, SOFTNESS 0/30/100) — Δ ≤ 0.01 dB; синус 1 kHz −3 dBFS, INPUT +6, CEILING −3, SOFTNESS 0 — пик −2.93 dBFS (на 0.07 dB выше потолка: ограниченная по спектру срезанная полоса, см. ограничения выше); MIX 0 % — выход = вход с задержкой 32 (−156 dB), MIX 50 % — ровно (вход + клип)/2 (−154 dB); UNITY при INPUT +12 — выход −12.00 dB, GR тот же; AUDIT — выход + AUDIT = вход после INPUT с задержкой (−144 dB); BASS 120 Hz, синус 50 Hz — гармоники ниже −170 dB; WAVE — 28–30 снимков в секунду (~224 КБ/с), сдвиг вход/выход 0 отсчётов; телеметрия 187 кадров/с, без meter — 0; нагрузка worklet 4.0 % ядра (прежний 3.8 %). В Chromium (1194×790): строка 48 px, TRANSFER 397×427, DISPLAY 629×427, блок CLIP 96×427, без прокрутки; угол, линии потолка (WAVE и LEVEL) и поля меняют те же значения, что ручки; ручка извне — рамка поля и через 0,6 с без рамки; крестик закрывает, UNITY и AUDIT выключаются, снимки WAVE при закрытом окне не идут; отрисовка 0.13 ms (WAVE) / 0.33 ms (LEVEL) на кадр.
- Взаимосвязь: DRIVE вверх — IN поднимается выше белой риски CEILING, GR растёт; CEILING вниз — риска на IN опускается, GR растёт, OUT ниже; SOFTNESS вверх — GR начинается раньше (колено) и растёт плавнее, срез мягче; BASS вверх — клипуется меньше (низ защищён), GR падает, OUT на материале с тяжёлым басом ближе к IN.
- Проверка: кроссовер — при DRIVE 0, CEILING 0 и уровне −12 dB выход = входу (±0.1 dB) при BASS 20, 100 и 300 Hz (шум и синус 1 kHz); синус 5 kHz 0 dBFS, DRIVE +6, CEILING −1, SOFTNESS 0, BASS OFF — пик выхода (сэмпл) не выше −1.0 dBFS (±0.05), GR около 7 dB; синус 50 Hz, DRIVE +6, CEILING −1, BASS 120 Hz (явно) — форма сохраняется, гармоники ниже −30 dB от основного тона; по умолчанию (BASS = OFF) синус 50 Hz 0 dBFS, DRIVE +6, CEILING −1 клипуется (пик не выше −1.0 dBFS); SOFTNESS 100% на 5 kHz — гармоник выше 15 kHz меньше, чем при 0%; синус 10 kHz, DRIVE +12, SOFTNESS 0, BASS OFF — алиасных компонент ниже −50 dB от основного тона; Bypass — OUT = IN, GR ноль, без щелчка, задержка не меняется. Ограничения: после возврата к исходной частоте срезанная ВЧ-полоса ограничена по спектру, и её пик может быть выше CEILING (синус 5 kHz, DRIVE +6, жёсткий клип — около −0.4 dBFS вместо −1.0); финальный срез на исходной частоте не делается — он дал бы алиасинг, такой пик ловит лимитер. Для меньшего алиасинга нелинейность считается с антипроизводной первого порядка (и коррекцией [−1/8, 5/4, −1/8]), задержка клиппера — 32 отсчёта. GR показывается, только пока нелинейность срабатывает (иначе 0).

## Лимитер мастера
По мотивам Ableton Limiter и FabFilter Pro-L 2. Стоит на мастере после клиппера, перед громкостью выхода.
- Ручки (колонка 4 в режиме MST, рядом с колонкой 3 клиппера; все плавные; вертикальный drag, мультитач; двойной тап без удержания ничего не делает; LFO и p-lock на них не назначаются):
  - 4.1 INPUT (на ручке подпись Input; ниже в тексте — GAIN): 0…+24 dB, шаг 0.1, по умолчанию 0 — входное усиление перед лимитером (чем больше, тем громче и сильнее лимитирование, как максимайзер).
  - 4.2 CEILING: −24…0 dB, шаг 0.1, по умолчанию −1.0 dB — наибольший уровень выхода (true peak).
  - 4.3 LOOKAHEAD: 0.5…6 ms, по умолчанию 3 ms — короче: транзиенты сохраняются лучше, но выше риск искажений; длиннее: безопаснее, звук сглаженнее (в Ableton 1.5 / 3 / 6 ms).
  - 4.4 RELEASE: 10 ms…1 s, логарифмическая шкала, по умолчанию 150 ms; последние 8% хода ручки — AUTO (на дисплее «AUTO»).
  - Значения: «+6.0 dB», «-1.0 dB», «3.0 ms», «150 ms» или «AUTO» — в центре ручки, как у всех ручек (подпись под ручкой).
- Кнопка LIM — справа вверху при MST (см. «Кнопки мастера»): тап открывает окно лимитера; SHIFT + тап — BYPASS LIM (включает и выключает; с SHIFT красная, пока bypass включён). В bypass лимитер полностью отключён (и GAIN тоже), переход кроссфейдом 10 ms без щелчка; линия задержки lookahead остаётся, чтобы задержка мастера не менялась; столбцы индикации серые, GR на нуле.
- Звук (AudioWorklet, стерео):
  - Вход · GAIN. Детектор stereo-linked на 100% (одно значение GR на оба канала, максимум из L и R), true peak: 4× оверсэмплинг (полифазный FIR) ловит межсэмпловые пики.
  - Lookahead: линия задержки на выходе по ручке LOOKAHEAD. Gain computer: целевое усиление g = min(1, Ceiling / Peak); скользящий минимум g за окно lookahead, затем сглаживание рампой (скользящим средним того же окна), чтобы усиление достигло цели ровно к приходу пика (brickwall, без перелёта).
  - RELEASE — экспоненциальный возврат с постоянной времени с ручки. AUTO — два этапа (быстрый 30 ms и медленный 400 ms), итог зависит от длительности лимитирования: короткие пики отпускаются быстро, долгое лимитирование медленно.
  - После лимитера на всякий случай жёсткий клип на уровне CEILING (страховка, в нормальной работе не срабатывает).
  - Float, без денормалов, без щелчков при смене параметров (значения сглаживаются за 20 ms); смена LOOKAHEAD плавная (кроссфейд задержек), без «прыжка» звука. Константы — в одном месте (начало limiter-worklet.js).
  - Нет: переключателя оверсэмплинга, стилей, Mid/Side, Release link, Audition, LUFS-метра в лимитере (позже).
- Индикация — блок LIM боковой панели мастера (общий компонент LevelBars, см. «Индикация мастера»): IN — уровень после GAIN, до лимитирования, риска CEILING; GR — лимитирование, шкала 0…−12 dB; OUT — уровень на выходе. Тап по блоку LIM или по кнопке LIM (при MST) открывает окно лимитера.
- LINK (lim.link, 0–100 %, по умолчанию 100 %; хранится в проекте, в старых — 100 %; ручки нет — поле в окне; p-lock и LFO/ENV не принимает): степень связи каналов. У каждого канала свой gain computer (свой true peak), плюс общий — по максимуму L и R (прежний); GR канала в dB = own + LINK·(linked − own). При 100 % звук совпадает с прежним бит-в-бит; при 0 % каналы независимы.
- Окно лимитера (src/ui/limiter.ts): на месте EQ (от левого края до края миниатюр страниц, справа общий измеритель; закрывает окно сэмпла, индикацию слева и сетку ручек; PATTERNS, EQ, редактор сэмпла, браузер, AUTO и окно не открыты одновременно). Закрывается крестиком ✕ и выходом из MST (дорожка, MIX); открытость не в проекте. Общий механизм «окно модуля мастера» (openMasterWindow, src/ui/masterwin.ts): у SAT, COMP, CLIP и LIM. Название окна слева в строке (MASTER SAT / COMP / CLIP / LIM ▾) — тап открывает меню SAT, COMP, CLIP, LIM (по цепочке, открытое — жёлтое): выбор переключает на окно этого модуля. Параметры — те же, что у ручек 4.1–4.4 при MST (и MIDI по позиции — Twister двигает элементы окна).
  - Сверху одна строка, как ряд EQ (той же высоты, 48 px; Swift: поля — той же ширины, что у CLIP): MASTER LIM, поля INPUT, CEILING (подписи — как у ручек 4.1 и 4.2), LOOKAHEAD, RELEASE, LINK, кнопки UNITY, AUDIT, BYPASS (рядом с крестиком) и крестик ✕ (закрыть). Параметр, который меняют (палец в окне, ручка, Twister, UNDO/REDO), — в жёлтой рамке и ещё 400 ms; при BYPASS поля INPUT и CEILING серые. Слайдера INPUT слева нет — INPUT меняется полем в строке (и ручкой 4.1).
  - Ниже: дисплей и справа блок LIM (тот же LevelBars и данные, что слева; IN и OUT — по SCALE из SETTINGS, GR — 0…−12 dB).
  - Дисплей — пик в dB во времени за 4 с (справа новое), каждый пиксель — максимум своего отрезка, без сглаживания, 60 fps, только пока окно открыто. Шкала: верх 0 dBFS, низ — SCALE 48 (по умолчанию), 32 или 16 dB (SETTINGS → SCALE; хранится в браузере, общая для окон модулей мастера), сетка через 6 / 4 / 2 dB с подписями. Слои: сетка; вход после GAIN — серая заливка с тонким контуром (выше 0 dBFS — светлая метка у кромки); выход — красный контур 1,5 px и красная заливка ~20 %; GR — оранжевая заливка сверху вниз на свою величину в dB по шкале; белая линия CEILING (в светлой теме чёрная) с числом справа — тянется пальцем (±22 px, приоритет над HOLD). Подписи пиков GR (оранжевые «-3.1»: локальные максимумы от 1 dB, не чаще 80 ms, до 6 самых сильных) уезжают с дисплеем; красная точка у кромки — выход выше CEILING больше чем на 0,1 dB. Тап по дисплею — HOLD (пауза: снимок истории, надпись HOLD; данные копятся), повторный — снять. Вход и выход — в одной метке времени.
  - Поля INPUT, CEILING, LOOKAHEAD, RELEASE, LINK (палец вверх-вниз — 240 px на весь диапазон, удержание — ввод числом — окно вверху окна лимитера; RELEASE: «auto» — AUTO, «1.2 s»), кнопки UNITY, AUDIT (жёлтые, пока включены), BYPASS (тот же BYPASS LIM).
  - UNITY — на выходе −GAIN dB (после лимитирования и страховочного клипа; GAIN не меняется, IN, GR, OUT — реальные). AUDIT — на выходе разность задержанного входа (после GAIN) и выхода лимитера (то, что срезано), кроссфейд 10 ms. Оба работают, только пока окно открыто: при закрытии и загрузке проекта выключаются, в проект не входят.
  - Двойной тап по элементам окна ничего не делает; отмена — общей UNDO. Мультитач: линия и поля — одновременно.
- Телеметрия: limiter-worklet.js раз в 256 отсчётов шлёт кадр [вход после GAIN (true peak, линейно), GR в dB (наибольшее по каналам), выход (true peak)] — только пока виден блок LIM (MST) или окно (сообщение meter); на главной стороне — кольцевой буфер 2048 кадров (~11 с); блок LIM — максимум последних 3 кадров (кадр экрана).
- Взаимосвязь: GAIN вверх — IN поднимается выше риски CEILING, GR растёт, OUT упирается в уровень CEILING; CEILING вниз — риска на IN опускается, GR растёт, OUT ниже; LOOKAHEAD на индикации почти не виден (чем короче, тем резче GR на коротких пиках); длиннее RELEASE — дольше GR возвращается к нулю.
- Проверка окна и LINK: node scripts/limiter-check.mjs [прежний worklet] — LINK 100 % против прежнего лимитера: разница −240 dB (совпадает бит-в-бит) на шуме при GAIN +12, +6 с AUTO, +18 с LOOKAHEAD 1 ms; пики только в L (синус 1 kHz 0 dBFS, GAIN +6): LINK 100 / 50 / 0 % — GR_R 7,02 / 3,52 / 0,02 dB при GR_L 7,02; UNITY при GAIN +12 — выход −12,00 dB, GR прежнее (10,66 dB); AUDIT — выход + AUDIT = задержанный вход (разница −138,5 dB); телеметрия — 187 кадров в секунду, без meter — 0; нагрузка worklet 3,9 % ядра (прежний 2,5 % — три gain computer). В Chromium: телеметрия вне MST без окна — 0 кадров; тап по LIM открывает окно, EQ его закрывает и наоборот; поворот ручки CEILING — рамка ячейки и через 0,6 с без рамки, UNDO — тоже рамка; крестик и выход в MIX закрывают, UNITY и AUDIT выключаются; отрисовка окна — 0,41 ms на кадр (2,5 % кадра 60 fps в headless Chromium с программной растеризацией холста; на iPad с GPU меньше).
- Проверка: синус 0 dBFS, GAIN +6, CEILING −1 — пик выхода не выше −1.0 dBTP (±0.1, замер с 4× оверсэмплингом), GR около 7 dB; синус fs/4 с фазой 45° при 0 dBFS (межсэмпловый пик) не превышает CEILING; Bypass — OUT = IN, GR ноль, без щелчка, задержка не меняется. Предел 4× оверсэмплинга: на сигналах с сильной энергией у Найквиста (шумовые всплески) более точный замер (16×) может показать межсэмпловый пик до ~1 dB выше CEILING; по 4×-замеру выход не выше CEILING. Задержка мастера = LOOKAHEAD + 10 отсчётов (фильтр детектора и удержание вокруг пика).
