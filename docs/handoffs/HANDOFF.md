# Handoff: JAMbo, Swift-версия — S11e (REC в редакторе сэмпла)

## 1. Контекст проекта
Groovebox для iPad. Веб (`src/`, `public/`) — эталон, заморожен. Swift-перенос — ветка `swift`, `ios/JAMbo.swiftpm`. Правила — `CLAUDE.md`, `ios/CLAUDE.md`; план и вехи — `docs/SWIFT_AUDIT.md` (раздел 6); итоги S11 — `docs/SWIFT_MILESTONE_S11.md`.

## 2. Принятые решения
- Переносим всё из веба (кроме браузерного); отличия — в «Решениях» `ios/CLAUDE.md` и в итогах вех.
- Порядок вех: S11 (a–e) → S12 MIDI → S13 автоматизация → S14 оптимизация и релиз.
- S11 разбита: S11a EXPORT/IMPORT .jambo, S11b библиотека, S11c ZIP/WAV/.jambopreset (готовы, проверены на iPad), S11d стемы и запись мастера, S11e REC в редакторе сэмпла.
- Решения пользователя в S11: миграции SPEECH нет; автоматизация веба при импорте не переносится; файл .jambo Swift — формат jambo-swift (в вебе не открывается); библиотека — Library.json в папке приложения, свои таблицы WTABLE — Tables/<ключ>.wav; свайп в списках — карандаш и корзина (без EXPORT); EXPORT библиотеки — кнопка в браузере; сэмплы выгружаются WAV 32-бит float; LOAD выбора закрывает браузер; SETTINGS → SAMPLER → CLEAR SAMPLE LOCKS (по умолчанию ON); чистка неиспользуемых сэмплов — позже; стемы — CAF float 32 (в вебе WAV 24 бит), правила в колбэке; ARM n и ARM MST — в S12.
- Термины (CLAUDE.md): сэмпл-лок — шаг со своим сэмплом, пресет-лок — шаг со своим пресетом синта.

## 3. Текущая задача
S11e: запись с входа в редакторе сэмпла (REC). Сначала свериться с вебом (docs/ai/sound-sampler.md — редактор, REC; src/ui/sampleedit.ts, stems.ts saveRecording — копия в RECORDINGS, папка «проект дд.мм.гггг»), уточнить у пользователя состав и отличия (вход AVAudioSession, разрешение микрофона — без своих ключей Info.plist?), затем план.

## 4. Что уже решено
- S0–S10, S11a–d готовы и проверены на iPad. CoreTests — 251.
- Запись из колбэка — StemRing (кольцо без потерь, prepare при первом нажатии) и StemCollector; папка и имя записи — Library.recordingFolderName, recordingName, recordingsFolder.
- Сэмплы — Samples/<ключ>.caf (ключ — SHA-256 исходного файла, 24 hex, как в вебе без 's:'); SampleStore.decode(bytes:name:dir), SampleStore.wav — для импорта и экспорта.
- Снимок звука: сэмплы папки, звука дорожки и сэмпл-локов шагов; extra — сэмплы вне дорожек (предпрослушка библиотеки).
- RECORDINGS — системная папка библиотеки (Library.recordings), есть с S11b.
- Новое поле модели проекта — в CodingKeys и init(from:) (ProjectCoding.swift); тест testCodingKeysCoverAllFields.

## 6. Важные ограничения
- Колбэк: без выделений, блокировок, Swift-коллекций; запись стема из колбэка — через кольцевые буферы, файл пишется вне колбэка.
- Только Swift и фреймворки Apple; файл ≤ ~600 строк; тело View ≤ ~40 строк.
- Playgrounds: выражения — по шагам с явными типами; UI на Linux не собирается — проверка только на iPad.
- Жесты в прокручиваемых списках: удержание — simultaneousGesture(LongPressGesture), не onLongPressGesture (задерживает прокрутку).
- Надписи — английские; комментарии и документы — русские. Окна закрываются квадратным ✕; меню закрываются тапом мимо.
- Markdown: путь, причина, точный текст — затем подтверждение.
- Тесты: `ios/tools/install-swift-linux.sh`, затем `. ios/tools/swift-env.sh && cd ios/CoreTests && swift test`.
- «Пришли проект» — полный zip ветки `swift` (`git archive`) в чат, не в рабочую папку репозитория. PR — только по просьбе.
- Скриншоты пользователя могут быть от старой сборки — сверять с последним коммитом.
