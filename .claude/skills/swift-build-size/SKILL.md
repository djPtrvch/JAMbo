# Объём сборки Swift-версии под Playgrounds

## Суть
Playgrounds на iPad собирает приложение отладочной сборкой целиком внутри себя. Когда сгенерированного кода слишком
много, сборка падает с «Build failed» без ошибок в списке, iPad греется; около порога — «со второго раза».
Это не выражение-«бомба»: проверка типов в проекте быстрая (самое медленное тело — ~0,3–0,5 с).

## Как замерить
1. Замер — по необходимости (решение пользователя): крупные правки интерфейса, сборка снова не с первого раза или
   просьба пользователя. Закоммитить правку в ветку `swift`, в сообщении коммита — метка `[calibrate]`; запушить.
   Архив для iPad после замера — только если сборка без ошибок.
2. Workflow `.github/workflows/swift-build-profile.yml`, задача `calibrate (HEAD)` (~3 мин, macOS, Xcode 26).
   Без метки задачи пропускаются (минуты Actions не тратятся); `[profile]` — полный профиль: время проверки
   типов по функциям и выражениям, память и объём IR по файлам (скрипты `ios/tools/build-profile-report.py`,
   `ios/tools/build-stats-report.py`).
3. Читать лог задачи через GitHub MCP (`actions_list` → `list_workflow_jobs`, `get_job_logs` с `tail_lines` ~185):
   - `CALIBRATION HEAD: memory … MB, IR insts N, IR functions …` — главное число N (повторяется в самом конце лога);
   - `CODE BYTES / TOP TYPES / TOP FUNCTIONS` — байты машинного кода по видам функций (value witness, outlined,
     closure…), по типам и по функциям: где объём (а не только число функций) — по ним выбирать правку;
   - `error:` / `BUILD FAILED` в шаге сборки — ошибка компиляции UI, исправить до отправки на iPad;
   - `FUNCTIONS total … / TOP FILES` — функции по видам и по файлам (где искать запас).
   Артефакт из облачной сессии не скачать (хранилище закрыто сетью) — всё нужное печатается в лог.
4. Сравнить с таблицей. Выше ~1,70 млн — облегчить до отправки на iPad.
5. Проверка на iPad (пользователь): ▶ в Playgrounds; результат — с первого раза, со второго или «Build failed».
   Перезагружать iPad не просить (решение пользователя, 9.11). Архив — `git archive --format=zip --prefix=JAMbo-swift/ origin/swift` в чат.

## Чем облегчать (что сработало, по выгоде)
- **Ресурсы:** импульсы комнат — ALAC в CAF (9.11, без потерь, вдвое меньше WAV; генератор пишет сам). Объём файлов в Resources тоже влияет на сборку (8.11: 1,533 млн с ресурсами 3,8 МБ — не собралось, без 1,9 МБ — с третьего раза). Короткие импульсы — 16 бит, длинные — 24 (качество хвоста); выровненный вариант EAR TONE — только ранняя часть.
- **Вложенные структуры модели — «в коробке»** (8.11, −104 тыс. за пять шагов): поле-структура (клип блока, звук
  клипа и дорожки) или редкие поля типа (TrackMore, ProjectMore) хранятся массивом из 0 или 1 элемента (`var box: [T]`,
  копия при записи), снаружи — прежнее свойство `get { box.first } set { box = ... }` (или `box[0].x`). Копия и
  сравнение внешней структуры (UNDO, проект в каждом виде) больше не тянут поля по значению: в TOP TYPES падают
  `outlined` и `value witness` у Track, Project, Clip, ArrBlock. Запись — своей `encode(to:)` по тем же ключам (формат
  файла прежний); тест ProjectFileTests.testCodingKeysCoverAllFields знает имена коробок. Признак кандидата — большие
  `outlined` и `value witness` у модели в TOP TYPES. Так же — пресет синта в LibNode и FolderItem (9.11: −7 и −2 тыс.).
- **DSP: редкие ветки — вызовом `@inline(never)`, а не копией `@_transparent` в каждом месте** (кроссфейды форм, скачки
  сброса SYNC): код функции ANALOG 30 → ~14 КБ, но инструкций IR — всего −3,5 тыс.; по байтам кода не судить, мерить
  CALIBRATION.
- **Значение, нужное почти каждому виду, — общее, а не @Environment.** Тема — Theme.current (ставит ThemedRoot,
  смена темы пересоздаёт дерево через .id): −65 тыс. инструкций (b2a144e). У каждого вида с @Environment своя
  обёртка — функции копирования и чтения.
- **Набор значений во многих видах — неизменяемый `final class`, а не структура.** Theme (23 цвета, в каждом виде
  через `@Environment(\.theme)`) — структура давала каждому виду функции копирования всех полей (value witness,
  outlined copy — 14 % кода): класс — −246 тыс. инструкций (e42dd98); ParamDef, EditorColors — ещё −12 тыс. Признак в
  TOP TYPES — у типа большие `outlined` и `value witness`. Можно, если поля `let`, нет сравнения структур и изменённых
  копий; в колбэке класс не читать (ARC) — для колбэка своя структура (ModScale).
- **Оформление, повторяющееся во многих видах, — функция, возвращающая `AnyView`** (`.tile`, `.framed`, `.menuBox`,
  `.menuPanel` в UI/PatternMenus.swift вместо `.modifier(Tile(...))` на каждом месте): −12 тыс. (7b685d0, 86 мест).
- **Наблюдаемые свойства простых типов — вручную** (UI/AppModelObserved.swift: access и put, без `_modify` и замыкания
  макроса) — около 145 инструкций на свойство (3.11: −20 тыс.). Проверка «изменилось ли» — одной функцией
  observedChanged без перегрузок: перегрузки одного имени Playgrounds не собирает («Replaced function … could not be
  found»), Xcode этого не ловит.
- **Повторяющаяся цепочка модификаторов — общий необобщённый ViewModifier** (MenuBox, Tile, Framed): 100–500
  инструкций на место; обобщённый модификатор (над типом жеста, TouchArea) — хуже, +1,9 тыс.
- **Меню и формы — списком, а не отдельной кнопкой в коде.** Ряды кнопок — `MenuChoice` + `MenuChoiceRow` /
  `MenuChoiceButtons` / `MenuChoiceColumn` (UI/PatternMenus.swift); формы (подпись, пояснение, ряд кнопок,
  рычажок, свой вид) — `FormRows` (UI/FormRows.swift: `.head`, `.label`, `.note`, `.choices`, `.toggle`, `.view`).
  EXPORT SONG так — −23 тыс. инструкций.
- **Большие ветки `if` / `switch` видов — `AnyView` в каждой ветке** (функция возвращает `AnyView`): центр экрана
  (RootView.center, `WithMeter`, `MainCenter`) — −22 тыс.; вкладки SETTINGS, меню аранжировщика, MIDI, мастера.
  Скрипт-образец для `@ViewBuilder`-switch: каждая ветка `return AnyView(...)`.
- **Длинная цепочка модификаторов (alert, onChange, fileMover…) — содержимое в отдельном свойстве, тело —
  `AnyView(содержимое)` и цепочка** (EqView `eqMain`, LibraryBrowser `libMain`, ProjectsMenu `projectsMain`).
- Убрали `@ViewBuilder` у функции или свойства — тело должно возвращать значение (`return`), у цепочки `if` без
  `else` — `return AnyView(EmptyView())` в конце; иначе ошибка компиляции (1.11, b6477cc).
- Поведение не меняется: состояние внутри ветки сохраняется (тип ветки тот же), `.id` внутри `AnyView` работает.
  ForEach по индексу в списках — только для строк без своего @State или с временным состоянием.

## Что не сработало
- Редкие поля клипа «в коробке» (ClipMore) — −0,2 тыс. (fb0c240, откат).
- Редкие поля шага (Step: lens, vels, sound, soundLocks) «в коробке» — −1 тыс. (f42cd4d, откат): шаг и так мал.
- Сеттер наблюдаемого свойства через общие willPut / didPut (один путь к свойству) — +2,3 тыс. инструкций
  (b3b9b9e, откат c6a9766): прежний `put` выгоднее.

## Где ещё запас (если понадобится)
- `AppModel` — @Observable: ~10 функций на наблюдаемое свойство (~1,5 тыс. из 2,5 тыс. функций файла).
  `@ObservationIgnored` — только свойствам, которые никакой вид не читает ни прямо, ни через вычисляемые
  свойства (иначе вид перестанет обновляться) — проверять по коду, при сомнении не трогать.
- По размеру кода (c2b80e1, TOP TYPES): AppModel 854 КБ (из них 85 КБ — setter наблюдаемых свойств), Track 230,
  Project 211 (модель — копии значений нужны для UNDO, не трогать), MenuItem 129 (closure 60 — кнопка в 98 местах),
  PatternGrid 114, LibraryBrowser 68, MenuScroll 56, MenuHead 47.
- Крупные файлы по IR ([profile], 98f01e7): AppModel 65 тыс., ArrangeWindow 44, PatternGrid 41, EqView 39,
  LibraryBrowser 38, RootView 33, ProjectsMenu 30, PatternMenus 30.
- SELF-TEST вынесен (1.11, 8896717): −41 тыс. инструкций; панда убрана (7.11, −8 тыс.); DIAGNOSTICS — **только по решению пользователя** (оставлен — решения 1.11 и 7.11).
- Таблицы данных (рисунки, прогрессии) — строками с разбором при вызове, а не литералами массивов, словарей и кортежей (7.11: −2,4 тыс.). Обобщённые функции `<G: RandomNumberGenerator>` против конкретного типа — выигрыша нет.

## Чего не делать
- Не ждать от упрощения выражений и проверки типов выигрыша — дело в объёме сгенерированного кода.
- Не менять Package.swift (только через Playgrounds), не добавлять unsafeFlags и модули.
- Не отправлять пользователю на iPad версию без замера, если она добавляет заметный объём UI.
