# JAMbo для iPad — Swift-версия (Swift Playgrounds)

Нативное приложение, App Project для Swift Playgrounds: `ios/JAMbo.swiftpm`, ветка `swift`. Поведение — как в веб-версии (корневой CLAUDE.md — эталон; веб заморожен, только исправления). Аудит и план вех — docs/SWIFT_AUDIT.md, итоги вех — docs/SWIFT_MILESTONE_Sx.md. Решение пользователя: переносим всё, что сделано в вебе (кроме чисто браузерного).

## Структура
- `JAMbo.swiftpm/Core/` — DSP и модель, только Foundation и Synchronization (без Accelerate, SwiftUI, AVFoundation; Accelerate — только под `#if canImport(Accelerate)` с обычной реализацией рядом). Util/ — AtomicFloat, AtomicCounter, SPSCQueue, CPUMeter; Engine/ — AudioCore (весь звук), события CoreEvent, TestTone; Model/ — Params (таблица параметров, как params.ts), Project (Step, Track, Project — поля как в вебе); Sequencer/ — TempoSource, SeqSnapshot, Sequencer, Click.
- `JAMbo.swiftpm/Audio/` — AVAudioSession (48 кГц, буфер 256) и один AVAudioSourceNode, колбэк зовёт `AudioCore.render`.
- `JAMbo.swiftpm/UI/` — SwiftUI.
- `JAMbo.swiftpm/Resources/` — таблицы Plaits (.bin), эталоны самотеста, лицензии.
- `CoreTests/` — пакет для сборки и тестов Core на Linux и Mac (`Sources/Core` — символическая ссылка на `JAMbo.swiftpm/Core`).
- `tools/` — install-swift-linux.sh (Swift 6.0.3 из пакетов Ubuntu в /opt/swiftdeb: swift.org из облака недоступен), swift-env.sh.

## Проверка в облаке
`ios/tools/install-swift-linux.sh` (один раз на контейнер), затем `. ios/tools/swift-env.sh && cd ios/CoreTests && swift test`. UI и Audio на Linux не собираются (нет SwiftUI и AVFoundation) — их проверяет сборка на iPad.

## Как открыть на iPad
GitHub → ветка `swift` → Code → Download ZIP → «Файлы» → распаковать → папка `ios/JAMbo.swiftpm` открывается в Swift Playgrounds (тап по ней). Package.swift — в виде, который создаёт Playgrounds; после открытия правится только через Playgrounds (ТЗ 0.3).

## Package.swift
Значок — только существующий `.placeholder(icon: …)` (с `.music` Playgrounds не читает манифест и показывает «Loading… Crashed» без кода). Устройство: iPadOS 26.6.2, Playgrounds 4.7 — S0 собирается.

## Правила кода
- Swift 5 (не режим Swift 6), минимальная iPadOS 18. Атомарные значения — модуль Synchronization (Atomic): SPSCQueue, AtomicFloat, AtomicCounter. Запасной вариант (если на iPad упадёт) — os_unfair_lock с tryLock в аудиопотоке (ТЗ 0.2; было в коммите S0 «replace Synchronization»). Только Swift и фреймворки Apple: без C, C++, Objective-C целей, сторонних пакетов, unsafeFlags, своих entitlements и ключей Info.plist (только редактор capabilities).
- Файл не длиннее ~600 строк; большие функции разбивать. Тело SwiftUI-View короче ~40 строк, остальное — в подвиды; сложные выражения — на несколько строк с явными типами (иначе «expression too complex»).
- Имена своих типов не совпадают с типами SwiftUI и Foundation (Scene, View, Text, Color, Button, Group, Section, Label, Menu, Toggle, Path…): Core и UI — один модуль, и своё имя закрывает системное (строка сетки Scene сломала `some Scene` в JAMboApp — теперь SceneRow). Числовые константы — готовым числом, без длинной арифметики из литералов (её компилятор Playgrounds не успевает проверить).
- Массивы-литералы не больше ~100 элементов; данные — из Resources.
- Колбэк (AudioCore.render и всё, что он зовёт): без выделения памяти, блокировок, ARC-объектов, созданных в колбэке, вызовов Objective-C, print и Swift-коллекций, которые растут; только final-классы, UnsafeMutablePointer<Float>, @inline(__always) на горячих функциях; денормалы в обратных связях гасить вручную (+1e-18 или обнуление). Каждый новый вызов в колбэке проверять по этому списку.
- Playgrounds собирает отладочную версию (DIAGNOSTICS → Build: Debug, без оптимизации; релиз для App Store — в разы быстрее). В горячих циклах DSP: без вызовов функций из других файлов на каждом отсчёте (отладка собирает файлы по отдельности — @_transparent и @inline встраиваются только внутри своего файла): интерполятор — значение и приращение в локальных переменных, синус/polyBLEP/фильтр — формулой или копией в своём файле; состояние класса — в локальных переменных на блок (иначе проверка доступа на каждом обращении); циклы while (for-in — итератор); без преобразований целых в целые и Int16/UInt32 → Float (обобщённые вызовы; фазы — Int по модулю 2³², таблицы — Float при загрузке); глобальные константы других файлов — в локальную переменную; enum с raw value не сравнивать в цикле. Проверка — сверка с эталонами (числа те же).
- UI → аудио: CoreEvent через SPSCQueue (простые значения, без ссылок) и AtomicFloat; аудио → UI: атомарные значения и кольцевые буферы, UI читает по таймеру (TimelineView). Экземпляры движков и буферы создаются вне колбэка и передаются в него на границе блока.
- Общий жест (DragGesture от 0 px) на контейнере перехватывает касания кнопок внутри него — кнопки и меню держать вне вида с таким жестом.
- Меню (все): не выше строки дорожек — низ меню не ниже верха кнопок дорожек; содержимое, которое не помещается, прокручивается пальцем (MenuScroll в UI/PatternMenus.swift), справа тонкая полупрозрачная полоса прокрутки, видна всегда, пока есть что прокручивать.
- Swift-файлы, которые пишутся из bash через heredoc в кавычках ('EOF'), — с одинарной обратной косой: `\(x)`, `\.self` (двойная попадает в файл как есть и ломает сборку).
- Вид, получивший индекс (страница, дорожка, шаг, ячейка), читает данные только с проверкой границ: @Observable перерисовывает его отдельно от родителя, и после удаления он может успеть отрисоваться со старым индексом (так падал DELETE страницы).
- Ручки, шаги, сетки, метры, скоп — Canvas; состояние — @Observable; без перерисовки всего экрана каждый кадр.
- Перенос из Plaits: в каждом файле «Ported from Mutable Instruments Plaits and stmlib (MIT), Copyright Emilie Gillet»; тексты лицензий — Resources/licenses.
- Все надписи — на английском; комментарии и документы — по-русски. Окна закрываются квадратным ✕.
- Каждая веха — файл docs/SWIFT_MILESTONE_Sx.md: что сделано, что проверено, что открыто.

## Решения
- Частота: всё считается на 48 кГц (формат узла 48000; если устройство даёт другую, приводит системный микшер).
- Plaits: a0 = (440/8)/48000, без сдвига ноты (A4 = 440 Гц, как в вебе после поправки на 47872,34 Гц). Эталоны tools/golden — wasm со сдвигом ноты −0,0461 полутона (так играет веб на 48 кГц).
- SPEECH: Formant, Phoneme, LPC (harmonics 0, 1/6, 1/3), без Words.
- FX и мастер — 1:1 по нынешним worklet’ам веба (Reverb FDN, Delay с FILTER/SPREAD, Drive 6 типов, sidechain с CURVE).
- Клипы (решение пользователя на проверке S1d, отличие от веба): у каждого клипа свой паттерн — страницы (до 8), длина, играющие страницы; копия клипа (перетаскивание, PASTE, «+» с COPY PLAYING, DUPLICATE и PASTE строки) — независимая, DELETE и p-lock меняют только свой клип; перетаскивание в другой столбец переносит шаги. В вебе клипы ссылаются на общие страницы дорожки. Импорт .jambo веба (S10): каждому клипу — копия страниц дорожки с его диапазоном.
- Секвенсор и пианоролл (решение пользователя перед S4, отличие от веба): ручные p-lock — жёлтая точка в левом верхнем углу шага (и на пустом шаге), свой звук шага — жёлтая обводка; в миниатюрах страниц и сетке паттернов p-lock не отмечаются; несколько играющих страниц — секвенсор показывает их все, 16 × N шагов в один ряд (с 3 страниц — без надписи ноты; удержание миниатюры — одна страница); зажат шаг + тап по другому — копия шага (триг, ноты, длина, p-lock, звук), при зажатом первом шаге двойной тап отменяет копию и ставит длину паттерна; 1 OCTAVE — PROGRESSION шириной 2 клавиши, аккорды по одной; ноты зажатого шага подсвечены на клавишах и аккордах прогрессии (аккорд, совпадающий с выбранными нотами, обведён белым).
- Фон: при уходе в фон звук останавливается (фоновый звук в Playgrounds не ожидается; если редактор capabilities даст Background Modes → Audio — вернуть BACKGROUND AUDIO).

## Вехи
S0 каркас (готов) → S1 секвенсор и экран → S2 сэмплер и редактор → S3a/S3b Plaits и свои движки, SELF-TEST → S4 FX, MOD, MORPH → S5 мастер, EQ, метры, скоп → S6 проекты и настройки → S8 автоматизация → S9 окна мастера, EQ Dynamic и M/S, пресеты EQ → S10 библиотека, импорт и экспорт, стемы, REC → S11 MIDI (CoreMIDI) → S12 переходы между проектами → S7 оптимизация и App Store. Подробно — docs/SWIFT_AUDIT.md, раздел 6.

## S0 (каркас)
- AudioHost: категория .playback, 48 кГц, буфер 256 кадров; перезапуск после прерывания и смены конфигурации; при уходе в фон — пауза и деактивация сессии.
- AudioCore: события из очереди в начале блока, тест-тон (синус 440 Гц, −12 dBFS, вкл./выкл. огибающей 5 мс — без щелчка), счётчик кадров sampleTime (основа транспорта).
- CPU: время колбэка (mach_absolute_time) / длительность блока, среднее за 0,5 с; индикатор справа вверху (≥ 70 % — красный); в DIAGNOSTICS — среднее и пик блока.
- Экран: бутерброд (APPEARANCE: SYSTEM, LIGHT, DARK — хранится в UserDefaults; DIAGNOSTICS), кнопка TONE (горит жёлтым), CPU. DIAGNOSTICS: «Now:» — фактические частота, буфер, задержка выхода, состояние («(48 kHz requested)», если система дала другую), секунды звука ядра, CPU; SELF-TEST — с S3a (см. S3a).
- Тесты CoreTests (7): очередь — порядок, переполнение, кольцо, два потока (200 000 элементов); AtomicFloat; тон — тишина до включения, −12,00 dB, 440 Гц, скачок между отсчётами на включении и выключении не больше, чем у синуса, через 200 мс после выключения — 0; CPUMeter.

## S1a (секвенсор и экран, часть 1)
- Модель: Project (bpm, scale, root, tracks), Track (params, pages, length, playFrom/playTo, mute, solo, stopped), Step (on, len, notes, locks, sound) — значения (struct); pageLen, playLen, playIndex — как в вебе. Params — таблица ручек дорожки (16, как TRACK_GRID): подписи, диапазоны, шкалы (curve, exp), форматы.
- Колбэк не читает Swift-коллекции: после каждой правки основной поток строит SeqSnapshot (плоские массивы: триги, длины, ноты до 8, Chance, Ratchet, Swing с p-lock), передаёт через очередь (Unmanaged), колбэк копирует указатели (SeqData), прежний снимок возвращает обратно — освобождается в основном потоке (releaseRetired, 60 раз в секунду).
- Sequencer (в колбэке): шаг k — в кадре timeAt(k/4)·48000 источника такта (InternalTempoSource), без планирования наперёд; Chance (xorshift), Ratchet (удары через шаг/n), Swing (нечётные шаги позже на (swing−50)/50 шага) — как в вебе; темп на ходу — со следующего шага (доля не прыгает); PLAY — первый шаг в первом кадре следующего блока. Метроном — щелчок 1000 / 1600 Гц (акцент), как clickAt веба, с точностью до отсчёта. Сработавшие ноты, позиции шагов и доли уходят в UI очередью SeqOut (звука нот пока нет — S2).
- Экран: верхняя панель как в вебе (меню, BPM — палец вверх-вниз 4 px на 1 BPM, удержание 0,5 с — ввод числом, полоса фазы 4 отрезка; метроном; SCALE, ROOT, UNDO, REC, REDO, AUTO, EQ, PATTERNS, ARRANGE — на местах, серые до своих вех; PLAY — по касанию, жёлтая); центр и пианоролл — заглушки; строка дорожек MIX | 1…8 | MST (тап — выбор, свайп вниз — mute, вверх — solo, мигание при нотах); секвенсор 16 шагов (SpatialEventGesture — мультитач: тап — триг с нотой C2, протягивание — длина, удержание первого шага + двойной тап — длина паттерна; играющий шаг — жёлтый контур). Тест-тон — в DIAGNOSTICS.
- Тесты CoreTests (15): шаги на 0 / 24000 / 48000… (120 BPM, блоки по 128); щелчок ровно на долю (24000) и акцент громче; рэтчет 4 и свинг 75 % — 0, 1500, 3000, 4500 и 9000; Chance 0 — ни одной ноты; темп 120 → 60 на ходу — 18000, 30000; длина и страницы (40 шагов, клип из страницы 3 — 8 шагов); стоп и новый старт — первый шаг в первом кадре; снимки освобождаются (в памяти один).

## S1b (сетка ручек, p-lock, страницы, UNDO)
- History<Project> (Core/Model/History.swift): снимок до действия (копия struct), жест — одна запись (beginGesture / endGesture: поворот ручки, протягивание шагов, BPM, выбор страниц протягиванием), до 200 записей, новое действие очищает REDO. UNDO не меняет, что играет (stopped дорожек остаётся). Кнопки UNDO / REDO в верхней панели, серые, когда нечего.
- TrackEdits (Core): changePages (длина растёт при полной, «играли все — играют все»), pageRange, setPlayPages, addPage, duplicate / copy / paste / clear / delete, nudge ◀ ▶ (по кругу через страницы) ▲ ▼ (октава, не за 0–127), toggleStep, setLock / clearLock / clearAllLocks, isTail, hasManualLocks — как state.ts веба.
- Ручки (KnobGrid): Canvas, геометрия веба (поле 100×100: кольцо r 36, дуга значения, p-lock — жёлтая дуга r 28 и жёлтая стрелка, шапка r 24); вертикальный ход 240 px, мёртвая зона 4 px; мультитач — SpatialEventGesture на всю сетку. С зажатым шагом (или несколькими) — p-lock на всех; двойной тап с зажатым шагом — снять p-lock; SHIFT (удержание) + двойной тап — снять все p-lock дорожки (с SHIFT ручки не крутятся). Без зажатого шага при игре ручки показывают p-lock играющего шага жёлтым. MIX и MST — ручки неактивны (S2/S5).
- Страницы (PagesColumn): 8 строк, под последней «+»; белая обводка — играющие; открытая — светлее; тап (через 0,3 с) — играет и открыта; протягивание — диапазон; удержание 0,45 с — открыть без смены играющих; двойной тап — меню (◀ ▶ ▲ ▼, duplicate, copy, paste, clear, delete — красная): своя панель под миниатюрой страницы, по центру колонки (как в вебе), тап мимо — закрыть (системный popover на iPad обрезался у края). Играющий шаг в миниатюре — жёлтый контур внутри ячейки. Перенос страницы удержанием и тяга края обводки — позже (S1d).
- Центр: левая колонка (окно сэмпла, стрелки, LFO1–3, ENV — серые), сетка ручек, правая колонка (страницы, MORPH, FX, SHIFT, MOD), измеритель (пустой).
- Тесты: 22 (добавлены History, страницы, nudge, p-lock, хвосты, шкалы параметров).

## S1c (пианоролл и запись нот)
- Core: Scales (11 гамм с сокращениями, 7 прогрессий, ноты по ступеням от корневой ноты октавы, трезвучия по гамме, названия C / Am / Bdim), AppSettings (pianoOctaves, velocity, record: quantize, overdub, autoRec — JSON в UserDefaults «settings», недостающие поля — по умолчанию), Recording (recordNotes: merge в дубле, OVERDUB, VELOCITY → p-lock Level по самой сильной ноте; recordLength — не дальше конца паттерна; clearPassStep), RecordClock (шаг по кадру: QUANTIZE — к ближайшему, OFF — вниз), PlayClock (seqlock: следующий тик, его кадр, длина шага, кадр и время хоста блока — пишет колбэк), History.serial.
- Запись с REC: шаг ноты = ход транспорта из PlayClock на момент «что слышно сейчас» (время хоста − outputLatency), не по кадру интерфейса. Дубль — одна запись в UNDO (пока history.serial не менялся); OVERDUB OFF — шаги дубля, по которым проходит игра, очищаются при сообщении step из колбэка (сам шаг в этом проходе уже прозвучал — в вебе очищался до звука; звука нот пока нет).
- Экран: пианоролл (CHORD, бутерброд — меню 1 / 2 OCTAVES и VELOCITY-рычажок, клавиши гаммы с мультитачем, строка PROGRESSION + аккорды, ▲ ▼ октавы); высота — квадратная клавиша (по двум октавам гаммы) + 50. Аккорды прогрессии, которые не помещаются по 2 клавиши, делят место поровну (в вебе — прокрутка). Режим CHORD, прогрессия и выбранные ноты — у каждой дорожки свои. SCALE и ROOT в верхней панели (палец 24 px на пункт, тап — меню-сетка), REC (красная).

## S1d (сетка паттернов)
- Модель: Clip (pages, length, playFrom, playTo, scale, root, fx — свой паттерн) в Track.clips[16]; активная ячейка slot (играет или запустится) и открытая open (секвенсор, миниатюры страниц, жёлтый контур; идёт за активной, если была ею; тап и удержание ячейки открывают её; не в UNDO); pages, length, playFrom, playTo дорожки — вычисляемые, открытого клипа; запись с REC — в играющий клип (Track.editing); снимок для колбэка — блок шагов на клип; SceneRow (имя, повторы); Project: scenes, rows, arrStart, arrEndStop, plusCopy (COPY PLAYING по умолчанию), rowLoop (по умолчанию ON), arrowSwitch. Правки (Clips.swift): putEmptyClip (клип с одной пустой страницей), fillRows, addRow, duplicate / delete / copy / paste строки, setScene (имя до 12, повторы 1…64), clearClip (DELETE ячейки очищает шаги всех страниц своего клипа, клип остаётся).
- Запуск — в колбэке (Core/Sequencer/Launcher.swift, как queuePattern / startScene / advanceScenes веба): клип ждёт конца прохода текущего клипа дорожки (остановленная — начала такта), строка — начала такта, стрелки SWITCH — конца прохода строки; повторы строк, LOOP ROW, AT THE END (STOP — транспорт сам останавливается, сообщение ended); PLAY — ожидающие сразу, иначе строка старта. Пока транспорт стоит, активные ячейки и остановки колбэк берёт из снимка проекта (интерфейс ставит их сам, без UNDO); при игре — свои, изменения уходят в интерфейс (clip, queue, scene, sceneQueue). Строки переставили во время игры — команда adoptPlay (ожидания и играющая строка сбрасываются). В render снимок проекта берётся до команд — PLAY сразу после правки видит новые клипы.
- Лидер (клип, запущенный последним; из одновременных — у выбранной дорожки, иначе самой левой): его гамма и нота — общие; правка SCALE / ROOT пишется и в его клип.

## S2 (сэмплер, микшер, окно сэмпла, редактор)
- Core/Sampler: SampleData (48 кГц float32, моно или стерео; у моно right = left), SampleEdit (TRIM, NORMALIZE −0,1 dBFS, MONO, огибающая для рисования), PitchDetect (YIN, как audio/pitch.ts — только индикация), Biquad (LP/HP по формулам Web Audio, Q в dB; Filter: влево LP 20 кГц → 30 Гц, вправо HP 20 Гц → 10 кГц, в центре LP 20 кГц; Q = 0,7 + reso/100·18), SoundSnapshot (ручки голоса дорожек, громкость, mute/solo, сэмплы папки с маркерами нарезки — строится на каждую правку, дёшево; держит ссылки на SampleData), Sampler (голоса в колбэке).
- Голос (как triggerTrack веба): сэмпл Start/End или маркер нарезки (нота маркера — от него до следующего, исходная высота; нота без маркера молчит), высота 2^((нота − 48 + Pitch)/12), кубическая интерполяция, край (End или конец файла) гаснет за 4 мс (не больше ¼ звучания) → Attack линейно (не меньше 1 мс) → удержание (нота от 2 шагов без рэтчета — до конца ноты, живая — до отпускания) → Decay как Release (экспонента, τ = max(5 мс, Decay/4)), голос останавливается через 2·max(20 мс, Decay) + 50 мс → Level (L/127)^1,5 → фильтр → Pan (StereoPanner: моно — cos/sin, по центру −3 dB в каждый канал; стерео — перекрёстно). Ручки дорожки меняют звучащие ноты сразу (сглаживание 10 мс, фильтр 15 мс; кусочки по 32 кадра), p-lock шага держит своё. Легато: нота той же высоты продолжает державшуюся — прежняя гаснет вместе с атакой новой (τ = max(1,5 мс, Attack/3)). Больше 48 голосов — самый старый гаснет за ~5 мс (ячеек 64). Смена звука дорожки на держащихся нотах — прежний голос гаснет за ~3 мс, новый звучит на оставшееся удержание (свой звук шага не трогается). Перестановка дорожек и убранные сэмплы — голоса гаснут за ~5 мс.
- Микшер: шина дорожки → громкость (dB, −∞…0, по умолчанию −10; сглаживание 10 мс) · гейт mute/solo (τ 1,5 мс, ноты играют дальше, дорожка не мигает) → выход (мастер — S5). Посылы и sidechain — S4.
- Секвенсор: шаг копирует в очередь ноты, p-lock голоса (Pitch, Start, End, Level, Attack, Decay, Filter, Resonance, Pan), свой звук шага и удержание — снимок к моменту рэтчета или свинга может смениться. Снимок паттернов строится заново, только если изменились шаги, клипы, строки или Chance/Ratchet/Swing (SeqSnapshot.same); снимок звука — на каждую правку. Прежние снимки освобождаются в основном потоке не раньше чем через 0,5 с (гаснущие голоса дочитывают их сэмплы).
- Живые ноты: клавиша пианоролла сразу звучит на выбранной дорожке и держится, пока держат (CoreEvent noteOn/noteOff по касанию); VELOCITY — p-lock Level ноты. Держат флажок маркера в редакторе — клавиша назначает ему ноту (занята другим маркером — флажок на 0,5 с красный) и звучит.
- Модель: Track.folder (ключи сэмплов, номер звучащего), Track.slices (маркеры по ключу сэмпла), Track.vol (dB); Project.files (имена), Project.roots (высота); правки — Core/Model/Sounds.swift (addSamples, stepFolder, stepFolderOnSteps, setStepSound, clearSample, replaceSample, маркеры, Slices.notes — как sliceNotes веба), TrackEdits (movePage, addTrack, deleteTrack, moveTrack, pasteTrack, renameTrack).
- Хранилище (Audio/SampleStore.swift): LOAD — системный выбор файлов («Файлы», iCloud Drive), можно сразу несколько; AVAudioFile → AVAudioConverter (48 кГц float32, не больше 2 каналов); ключ — SHA-256 файла; копия — Application Support/Samples/<ключ>.caf; правки — новый ключ по отсчётам. Декодирование вне основного потока.
- Окно сэмпла (левая колонка): имя · высота · ST/M, форма волны (стерео — L и R), Start/End затемняют отрезанное, полосы воспроизведения (тают за 1,2 с; позиция — по времени хоста с поправкой на задержку выхода); с зажатым шагом со своим звуком — его звук. Тап — меню звука, удержание 0,5 с (без зажатого шага) — редактор. Стрелки ◀ ▶ — папка дорожки (с зажатым шагом — звук шага), между ними n / всего. MIX — MIXER и ● MASTER (S10, серая); MST — S5.
- Меню звука (на месте левой колонки): SYNTH (DRUM, ANALOG, FM, WTABLE — S3, серые; SAMPLER — дорожка без звука и чистый редактор), MI SYNTH и MI DRUMS (S3, серые), LOAD, MIDI (S11; для шагов — TRACK), SAVE и TABLE (S3/S10).
- Редактор (на месте центра, справа измеритель): строка — имя, длина (выделение), ST/M, REC (S10, серая), ▶ (выделение или весь сэмпл в исходной высоте, −3 dB, сразу на выход; повторный тап — стоп), LOAD, SAVE (S10), TRIM, NORMALIZE, MONO, CLEAR, ✕. Поле: маркеры обрезки за ручки внизу (оба сразу двумя пальцами), над пальцем — время; палец по пустому месту — вверх-вниз масштаб (точка под пальцем на месте, до 256 отсчётов на окно), вбок — прокрутка (направление — после 10 px), полоса прокрутки сверху; второй палец по пустому месту ничего не делает; двойной тап — маркер нарезки, флажки (пятиугольник с нотой) тянут, двойной тап по флажку — удалить. Масштаб и выделение — не в проекте.
- MIX: ручки — громкости дорожек (подпись — имя), слева от ручки — дорожка метра (S5), справа M, S, ● (стем — S10); двойной тап — COPY, PASTE, DELETE TRACK (больше 8), RENAME (поле на месте подписи), по серой ручке — ADD TRACK; удержание ручки 0,5 с и протягивание — перестановка (соседи сдвигаются, выбранная дорожка остаётся выбранной). Свой секвенсор MIX (p-lock громкостей) — S5, вместе с MST.
- Страницы: удержание миниатюры 0,45 с — страница открыта и поднята (тень, крупнее; не у самой границы обводки — там край обводки); протягивание — перенос (идёт за пальцем без порога, соседи сдвигаются; обводка одной перенесённой идёт за ней; одна запись в UNDO).
- SETTINGS → SAMPLER → SLICE NOTES (CHROMATIC / SCALE) — в меню бутерброда. Ноты маркеров по порядку — от первой клавиши пианоролла (корневая нота его октавы; решение пользователя, в вебе — от C3): CHROMATIC — по полутону, SCALE — клавиши пианоролла по порядку; октава пианоролла сменилась — ноты маркеров тоже.
- Строка дорожек: тап — выбор дорожки (на отпускании), свайп вниз — mute, вверх — solo — без выбора дорожки (окно MIX и выбранная дорожка остаются; решение пользователя).
- Экран не сдвигается клавиатурой (ignoresSafeArea(.keyboard)): поля ввода — в верхней части. Окно сэмпла — огибающая сплошной фигурой (160 столбцов; штрихи давали муар). CPU — как в вебе: две строки 9 pt обычным шрифтом, цвет dim.
- Нагрузка (виртуалка разработки, 48 стерео-голосов с фильтром): релизная сборка — 3,5 % одного ядра, отладочная — ~42 %. Playgrounds, вероятно, собирает отладочную — проверить CPU на iPad; оптимизация — S7.
